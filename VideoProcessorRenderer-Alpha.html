VideoProcessor Renderer (Alpha): display rules

The renderer maintains a persistent compiled-shader cache at libplacebo\VideoProcessorShaderCache.bin beside the application. The cache reduces shader compilation pauses on later launches. It is performance-only: missing, stale, or corrupt data is ignored and rebuilt. The file may be deleted while VideoProcessor is closed to force a clean rebuild.

Internal alpha guide. This document is intentionally not linked from the normal configuration guide or included in releases. The renderer and these rules remain experimental.

Configuration model

Display rules live in VideoProcessorRenderer.cfg. The base [display] section contains the normal renderer settings. A matching rule overrides only the settings written in that rule; every omitted setting continues to use the base value.

There are three layers, applied in this order:

  1. Built-in defaults provide a safe value when a key is absent.
  2. [display] changes the base renderer configuration for every source.
  3. One selected [display_rules.name] section overrides only its explicitly configured renderer keys.
[display]
# Base value used by every source unless the selected rule overrides it.
quality=high
tone_mapping=AUTO

[display_rules]
# This list enables rules and defines the tie-breaking order.
rules=hdr,sdr

[display_rules.hdr]
rule=$eotf==PQ|HLG|HDR
priority=100
# Only this setting changes for the HDR rule; quality remains "high".
tone_mapping=spline
One rule at a time. Matching rules are not merged. VideoProcessor selects one winner, applies that rule over [display], and ignores the other matching rules.

SDR and HDR defaults

The supplied configuration separates SDR from HDR-family input without changing output range, output gamma, target nits, scaling, or refresh switching. Those remain controlled by [display].

[display_rules]
rules=hdr,sdr

[display_rules.hdr]
rule=$eotf==PQ|HLG|HDR
priority=100
tone_mapping=spline
gamut_mapping=perceptual
peak_detection=AUTO

[display_rules.sdr]
rule=$eotf==SDR
priority=90
tone_mapping=AUTO
gamut_mapping=AUTO
peak_detection=OFF

Rule syntax

  • && joins required conditions (AND); || joins alternatives (OR).
  • | lists accepted values for one equality condition, such as $eotf==PQ|HLG.
  • Use ==, !=, <, <=, >, or >= for comparisons. Single = remains supported for older configurations.
  • Parentheses group expressions. Evaluation order is !, then comparisons, then &&, then ||.
  • Boolean variables may be abbreviated: $hdr_metadata means $hdr_metadata==true, and !$hdr_metadata means false.
  • Names and values are case-insensitive. Quotes are optional around a single value.
  • Numeric equality supports inclusive ranges, such as $source_rate==23-30. Relational operators take one number, such as $width>=3840.
# 23.976/24/25/29.97/30 Hz HDR-family input
rule=$source_rate==23-30 && $eotf==PQ|HLG|HDR

# The same idea using relational comparisons and grouping
rule=($eotf==PQ || $eotf==HLG) && $source_rate>=23 && $source_rate<31

# SDR BT.2020 input with valid static HDR metadata is unusual, but expressible
rule=$eotf==SDR && $colorspace==BT_2020 && $hdr_metadata

# Any progressive 4K source except SDR
rule=$width>=3840 && $height>=2160 && !$interlaced && $eotf!=SDR

| versus ||

These operators are intentionally different. A single | belongs to one comparison and lists acceptable values. A double || joins complete expressions.

# Compact value list:
$eotf==PQ|HLG|HDR

# Complete alternatives; useful when each branch has different conditions:
($eotf==PQ && $source_rate==23-30) || ($eotf==HLG && $source_rate==50-60)

Available input variables

Rules use the capture state known to VideoProcessor—not a filename, media-library tag, or renderer guess. A variable that is unavailable does not match, including a != comparison.

VariableTypeMeaning and examples
$source_rateNumberTruncated input frame rate: 23.976 becomes 23, 29.97 becomes 29, and 59.94 becomes 59. Example: $source_rate==23-24.
$eotfTextEffective input transfer classification: SDR, HDR, PQ, HLG, or UNKNOWN.
$colorspaceTextEffective capture colorspace, for example REC_709, BT_2020, P3_D65, P3_DCI, or P3_D60.
$hdr_metadataBooleantrue only when valid static HDR metadata is present; otherwise false. This is independent of the EOTF classification.
$widthNumberCapture raster width, such as 1920 or 3840.
$heightNumberCapture raster height, such as 1080 or 2160.
$resolutionTextExact capture raster written as widthxheight, for example 3840x2160.
$interlacedBooleantrue or false from the active DeckLink display mode.

Source rate is deliberately truncated. Use 23 for 23.976, 29 for 29.97, and 59 for 59.94. This is the same convention used by [refresh_rate_commands].

When a rule takes effect and how the winner is selected

The selected rule is read when the renderer starts. A later input transition that selects a different rule requests a normal renderer rebuild, so renderer-output settings never change underneath queued frames. This is deliberate: rules are not a per-frame processing path.

  1. Only names listed in [display_rules] rules=... participate.
  2. Every listed rule expression is evaluated against the current source state.
  3. The matching rule with the highest integer priority wins. Priority defaults to 0.
  4. If priorities tie, the rule with more required comparisons is considered more specific and wins.
  5. If both priority and specificity tie, the rule appearing first in rules=... wins.
[display_rules]
# "hdr_4k_slow" wins over "hdr" for 4K 23-30 Hz HDR because it has
# both a higher priority and more conditions.
rules=hdr_4k_slow,hdr,sdr

[display_rules.hdr_4k_slow]
rule=$eotf==PQ|HLG|HDR && $width>=3840 && $source_rate==23-30
priority=200
quality=high

[display_rules.hdr]
rule=$eotf==PQ|HLG|HDR
priority=100

[display_rules.sdr]
rule=$eotf==SDR
priority=90

If no rule matches, the renderer uses the base [display] settings and reports the active rule as None.

Manual profile shortcuts

A named display rule may also have a shortcut=. Pressing that shortcut selects the rule as a manual override even when its rule= expression does not currently match, and safely rebuilds the renderer when needed. The selected rule remains active across source changes until either another profile shortcut or display_rules_auto is pressed. This is suitable for fixed display-calibration profiles such as Rec.709 on F5 and BT.2020 on F6.

sdr_target_primaries=REC709|BT2020 controls the actual SDR render target. A BT.2020 target is applied whether or not GPU signaling is enabled or succeeds. report_bt2020_to_display=true is a separate NVIDIA-only option: VP uses NvAPI_Disp_InfoFrameControl to report BT.2020 in the HDMI AVI InfoFrame, verifies the effective InfoFrame, and restores the captured prior InfoFrame when switching back to Rec.709 or tearing down the renderer. Use this signaling option with caution. On unsupported hardware or an NVAPI failure, VP logs the failure and continues rendering BT.2020 so a display gamut may be selected manually.

[display_rules]
rules=hdr,sdr

[display_rules.hdr]
rule=$eotf==PQ|HLG|HDR
priority=100
shortcut=F5

[display_rules.sdr]
rule=$eotf==SDR
priority=90
shortcut=F6

[shortcuts]
# Return immediately to normal automatic rule selection.
display_rules_auto=F4

A rule may be both automatic and manually selectable. For a manual-only profile, give it a valid condition that real input cannot satisfy, such as $width==0. Startup validation still checks the expression, but automatic selection will never choose it.

[display_rules]
rules=hdr,sdr,bright_demo

[display_rules.bright_demo]
# Manual-only: a real capture width is never zero.
rule=$width==0
shortcut=Ctrl+F7
priority=0
sdr_target_nits=300
contrast_recovery=0.25
Shortcut conflicts: if two actions use the same shortcut, the later duplicate is ignored and written to the log. Use display_rules_auto to leave manual mode immediately.

Screen-profile shortcuts (screen_profile_normal and screen_profile_scope) are independent: they choose the output viewport and do not replace a display rule.

Not rule overrides: scope-screen geometry, subtitle-fit settings, screen-profile defaults, shortcuts, and refresh-rate commands are global renderer behavior. Put those in their documented sections rather than inside a display rule.

Startup validation and troubleshooting

VideoProcessor validates VideoProcessorRenderer.cfg before creating the UI or capture graph—even when a different renderer is selected. A malformed rule stops startup and displays a detailed error instead of silently falling back to the wrong rendering profile.

Startup validation catches:

  • a name listed in rules= without a corresponding section or rule= expression;
  • unknown variables, missing values, unsupported operators, malformed ranges, and unbalanced parentheses;
  • text or Boolean variables used with numeric relational operators;
  • ordinary configuration syntax problems reported by the shared configuration reader.

Renderer-setting values are checked when the renderer loads. An invalid override is logged and the inherited/base value is retained. Invalid or duplicate shortcut bindings are also logged and ignored.

Useful checks

  1. Confirm the file being edited is beside the running VideoProcessor.exe.
  2. Check the OSD Shader Rule line. None means no automatic rule matched.
  3. Search the current log for display: selected, input state selects rule, or Invalid ... [display_rules].
  4. Remember that 23.976, 29.97, and 59.94 use source-rate keys 23, 29, and 59.
  5. After changing the configuration, restart the renderer or VideoProcessor so the selected settings are rebuilt safely.

Scope subtitle fit

The Scope profile automatically detects stable encoded letterbox bars and crops them before fitting the active picture to the configured scope screen. Thus scope content fills the scope viewport, while 16:9 content remains correctly pillarboxed. Once established, the picture boundary remains locked through dark frames and temporary overlays when either edge still supports it; a different aspect must remain stable across several analyses before replacing the lock.

The optional subtitle fit deliberately uses a simple heuristic rather than OCR or the hidden experimental subtitle processor: meaningful non-black content found inside either confirmed encoded black bar is treated as content that must remain visible. It does not need to recognize words, glyphs, language, alignment, or subtitle style. Lower-bar content snaps the picture upward; upper-bar content snaps it downward. When both bars contain content, the side requiring the larger adjustment wins.

Every analysis that still sees bar content restarts the configured hold timer. When that content disappears, the exact picture adjustment remains active for the full configured interval and then snaps back; it does not ease, drift, or release early. A newly detected item at the opposite edge changes direction immediately. Normal screen profile and other renderers do not use this path.

[display]
scope_screen_aspect=2.35:1
scope_subtitle_fit=true

# Keep the exact picture adjustment after bar content disappears.
# Every new detection restarts this timer.
# Default: 2 seconds. Valid range: 0 to 30 seconds.
scope_subtitle_hold_seconds=2

# Extra source pixels outside the detected subtitle bounds.
# Default: 20. Valid range: 0 to 500 pixels.
scope_subtitle_padding_pixels=20

The hold avoids flicker during brief detection gaps and between adjacent subtitle frames. Padding is added to the existing safety margin, so increase it only when subtitle or overlay edges are being clipped. When bar content needs more room than its letterbox bar provides, subtitle fit shifts the picture farther in the required direction and may crop picture content at the opposite edge; keeping the detected bar content fully visible takes priority.

Refresh-rate commands

Entries in [refresh_rate_commands] map a truncated display rate to a complete command line. Set delay_seconds to a whole number from 0 to 30 (default: 5) to control when commands run after the renderer applies or confirms the refresh rate; use 0 for no wait. The delay allows the final fullscreen/window state to settle before a script inspects the window or sends shortcuts. Exact entries take precedence over wider ranges.

[refresh_rate_commands]
delay_seconds=5
23-24=C:\Videoprocessor\audio\audio_delay.bat 315
59-60=C:\Videoprocessor\audio\audio_delay.bat 285

This section is separate from display-rule selection. It uses the resulting output/display rate and launches the configured command through the Windows command processor; it does not change a renderer profile. The narrower matching range wins when ranges overlap.

SDR transfer comparison

sdr_input_transfer controls how captured SDR sample values are interpreted before rendering. It is intentionally separate from output_gamma, which describes the render target. The default AUTO uses VideoProcessor's normal SDR mapping (BT.1886). For a controlled A/B comparison, test the same paused SDR frame with AUTO, 2.2, and 2.4, restarting the renderer after each change. Do not use this setting to compensate for an output-level mismatch.

[display]
output_gamma=AUTO
sdr_input_transfer=AUTO

For the normal DWM-composed SDR path, leave output_gamma=AUTO. The swapchain currently negotiates RGB_FULL_G22_NONE_P709; forcing a 2.4 render-target transfer while Windows continues interpreting the surface as G22 produces a visible brightness mismatch. A physical display calibrated to gamma 2.4 does not by itself justify overriding the DWM swapchain transfer.

output_range=LIMITED requests a Studio-range DXGI swapchain and encodes the render target as limited only when the active output advertises that exact color space before configuration and DXGI accepts it. If the driver, monitor, or presentation model rejects it, VideoProcessor logs the complete probe and safely restores the Full/sRGB swapchain contract; it never writes limited values into a target Windows still interprets as Full. DXGI acceptance proves the swapchain interpretation, not the HDMI wire encoding. Validate the physical link with a known PLUGE/grayscale pattern and matched display range.

Do not use output refresh rate as a condition. It is a display result rather than a source property and would create avoidable feedback between rule selection and display switching.
