VP-0079 configuration model proposal

A single-file, namespace-based configuration model for VideoProcessor.

Design for review — not current runtime syntax. The current binary still uses profile groups, the legacy shader registry, and refresh-only event actions. Do not deploy this grammar until its implementation lands.

Goal

VideoProcessor has one VideoProcessor.cfg. Settings live with the component that owns them. Named variants use the same when: expression language as other conditional behavior. There are no duplicate profile lists, disk-persisted profile selections, renderer side files, or shader-only shortcut grammar.

Separate render.cfg, directshow.cfg, and videoprocessor.cfg files are intentionally out of scope. Queue policy, source state, renderer transitions, shaders, and external actions must validate and deploy atomically. Includes can be considered later, but only as one merged configuration snapshot.

Namespaces and ownership

NamespaceOwner and purpose
[general]Application-wide startup and capture choices. No selectable profile settings.
[queue]VP-owned queue policy, regardless of selected renderer.
[directshow]DirectShow pipeline/timestamp/input-conversion configuration.
[directshow.ppm]DirectShow source-timing PPM policy.
[vprenderer]Alpha / VideoProcessor Renderer output, tone-mapping, scaling, and presentation settings.
[vprenderer.viewport]Alpha viewport and subtitle-fit configuration.
[shader]Common external-shader selector; variants may carry HLSL and/or GLSL files.
[actions.*]External commands started for committed VP events.
[renderer_alias]Friendly aliases for UI renderer indices; not an ownership namespace.

[renderer_alias] mappings must be checked against the resolved renderer order at startup. A stale mapping is a configuration error, not a silent change in action scope.

Root and variant profiles

An exact registered root is the baseline. A named child overlays values in the same domain. There is no profiles: list or default: field, and source-file order is never meaningful.

[queue]
when: $key=="l"
queue_size: 32
target_frames: 2

[queue.low_latency]
when: $key=="L"
queue_size: 1
target_frames: 1

Registered domain roots may contain dots. One extra identifier names a variant, so [directshow.ppm.film] is a directshow.ppm variant and [vprenderer.viewport.scope] is a vprenderer.viewport variant. This is not arbitrary INI inheritance.

Selection and evaluation

Rules are evaluated on source-state changes, component rebuild/start, and registered key events — never once per frame. A changed state is not automatically a rebuild.

source/key event → immutable state snapshot → resolve automatic rules and manual selections → compare effective values → apply live changes or request a rebuild only when required

A source-only rule is automatic. A key-qualified rule is evaluated with the current source snapshot and installs a manual in-memory selection when it matches. That selection survives refresh-rate transitions and renderer rebuilds, but is discarded when VP exits. Nothing is written to disk.

[shader.nls_hdr]
when: $key=="N" && ($transfer=="PQ" || $transfer=="HLG")
type: nls
hlsl_file: NLS.hlsl
glsl_file: NLS.glsl

Source terms in a key-qualified expression are eligibility checks at key-press time. A manual selection wins over later automatic evaluation until a different key/root selection replaces it. A root key condition clears manual selection and returns to baseline plus any applicable automatic variant.

Shader model

[shader] is a valid empty baseline: it permits automatic matching but forces no manual shader. A logical shader configuration contains its selection rule and explicit backend files. Duplicate same-hotkey HLSL/GLSL rules disappear.

[shader]

[shader.off]
when: $key=="n"
selection: none

[shader.nls]
when: $key=="N"
type: nls
stage: pre_resize
hlsl_file: NLS.hlsl
glsl_file: NLS.glsl
hlsl_quality: high
geometry: classic
strength: 1.0
curve: 2.0

selection: none is a manual selector state, not a global shader capability switch. It suppresses automatic shader matching for the current VP process. Missing backend files are valid; that configuration simply has no implementation for the active backend.

DirectShow PPM

PPM correction comes from DirectShow source timing, not output display refresh. It uses $source_rate, not $actual_refresh.

[directshow.ppm]
ppm: AUTO

[directshow.ppm.film]
when: $source_rate<=30
ppm: -17

[directshow.ppm.video]
when: $source_rate>30
ppm: -14

A changed PPM value starts a new DirectShow timing epoch; VP must never alter timestamp trim mid-epoch.

Actions

Actions are external side effects, not profiles. Every [actions.<name>] section is discovered directly. run: is one Windows command line; relative paths resolve beside the configuration file.

[actions.audio_delay_film]
on: refresh.applied,refresh.confirmed
when: $actual_refresh<=30
run: C:\Videoprocessor\audio\audio_delay.bat 100

[actions.signal_lost]
scope: *
on: signal.lost
run: C:\Videoprocessor\automation\signal-lost.cmd
ScopeMeaning
vprendererAlpha / VideoProcessor Renderer events; the documented default.
directshowDirectShow pipeline events.
*All matching scoped events. It runs once per emission, so multiple producers may launch it more than once.

Target event families: refresh.*, source.changed, picture.changed, profile.changed, renderer.*, and signal.*. An event is published only after a committed transition and exposes one documented immutable variable context.

Required implementation work

  1. Discover registered domain roots and variants, including dotted roots.
  2. Resolve root plus selected variant values through one central runtime.
  3. Retain manual selections only in memory across renderer transitions.
  4. Move DirectShow PPM and shader selection onto the common resolver.
  5. Make renderers consume a resolved snapshot rather than independently re-read raw configuration.
  6. Replace refresh-only Alpha actions with a scoped VP event dispatcher.
  7. Validate all sections, expressions, aliases, scopes, command targets, and typed values before capture starts.

Until that work is complete, production configuration must continue using the current supported grammar.
