VideoProcessor configuration reference

The shipped VideoProcessor.cfg is one strict, startup-read configuration file. This reference describes the supported public settings for capture, DirectShow, the VideoProcessor Renderer (Alpha), shader selection, and refresh actions. It is deliberately value-level: use it to decide what a setting changes before editing your working configuration.

Start conservatively. Copy only the setting that solves a known problem, keep your prior value in a comment, and change calibration-related values only when they match the display or LUT you actually use. Configuration is read at startup; a renderer rebuild may apply a newly selected Alpha or viewport variant, but editing the file itself requires restarting VideoProcessor.
Strict syntax matters. A malformed public setting is rejected during startup validation or reported in vp_debug.log. Names are case-insensitive, but the spelling and section shown here are the supported contract. AUTO means VP leaves a choice to its built-in resolution path; it never means "try every upstream library option."

How to read and compose the file

Sections own settings. A root section is the normal baseline. A named child section is a variant that inherits its group's baseline and replaces only the keys it declares. A matching when expression selects the variant in memory. Selecting a root expression returns that group to its baseline; it does not retain keys from the previous variant. Selections are process-local and disappear when VP exits.

Startup, capture, and renderer selection

[general] capture_device

Purpose: chooses the capture device VP opens at startup. Syntax: the exact device name displayed by VP or its capture backend. Omitted: VP uses its normal device-selection path.

ValueMeaning
Exact device nameRequests that installed capture device; retain punctuation and any adapter suffix.
OmittedDoes not force a device and lets the normal startup choice apply.

Effect and verification: This is a startup-only choice. Check the startup portion of vp_debug.log for the selected device; an unavailable name is not a portable preset.

[general] renderer

Purpose: selects the startup output renderer. Syntax: exact renderer name from VP's renderer selector. Omitted: VP keeps its normal renderer selection.

ValueMeaning
VideoProcessor Renderer (Alpha)Starts the built-in libplacebo-based Alpha renderer; the [vprenderer] settings in this document apply.
An installed renderer nameStarts that renderer. Its own settings, capabilities, and latency differ.

Effect and verification: Startup-only. The selected renderer is logged and visible in the VP UI. Do not use an Alpha profile as evidence that madVR has received the same setting.

[general] fullscreen

Purpose: requests fullscreen startup. Syntax: true or false. Omitted: uses VP's normal window startup behavior.

ValueMeaning
trueRequest fullscreen at startup.
falseStart without requesting fullscreen.

Effect and verification: Fullscreen transitions can recreate renderer resources. Confirm the final output mode in the UI and log rather than assuming the request was accepted by every display path.

[general] windowed_fullscreen_mode

Purpose: chooses VP's borderless/windowed fullscreen mode when fullscreen is requested. Syntax: a Boolean. Omitted: leaves the normal fullscreen mode unchanged.

ValueMeaning
truePrefer VP's windowed fullscreen path.
falseDo not request the windowed fullscreen path.

Effect and verification: This is an output-window policy, not an Alpha presentation setting. Test it with the actual display and renderer because compositor behavior is platform dependent.

[general] startminimized

Purpose: controls whether the VP control window starts minimized. Syntax: a Boolean. Omitted: normal UI startup.

ValueMeaning
trueStart the control window minimized while the configured output continues starting.
falseShow the normal control window.

Effect and verification: It does not disable capture, rendering, or diagnostics; it changes only initial UI visibility.

[general] scene_detect

Purpose: enables VP's scene-detection policy where the active renderer and pipeline support it. Syntax: a Boolean. Omitted: leaves the normal pipeline default.

ValueMeaning
trueAllow scene-aware cadence and related logic to run.
falseDo not request scene detection.

Effect and verification: Scene analysis can add work and log activity but is not a substitute for renderer queue policy. Inspect scene/cadence messages in vp_debug.log.

[general] disable_detection_features

Purpose: safely disables optional detection-driven features while retaining normal playback. Syntax: a Boolean. Omitted: detection features remain eligible when enabled elsewhere.

ValueMeaning
trueSuppress optional detection features such as detection-led actions.
falsePermit configured detection features.

Effect and verification: Use this as an investigation switch when a detection feature is suspect. VP logs that an otherwise requested feature was ignored by configuration.

[general] scene_correction_basic

Purpose: allows the basic scene-correction policy. Syntax: a Boolean. Omitted: uses VP's normal correction policy.

ValueMeaning
truePermit the conservative Basic correction path where it is available.
falseLeave Basic correction disabled.

Effect and verification: This is a cadence policy, not an image-processing preset. Confirm corrective activity through the cadence diagnostics before deciding it helped.

[general] hdr_colorspace

Purpose: specifies the HDR input colorspace metadata policy presented by DirectShow. Syntax: a supported capture/input metadata token. Omitted: leaves input metadata policy at its normal resolver behavior.

ValueMeaning
FOLLOW_INPUT_LLDVUse the incoming LLDV-associated colorspace interpretation when the source supplies it.
Capture-format tokenRequests that explicit input metadata policy; use only a value supported by the connected capture path.

Effect and verification: This describes input metadata, not the Alpha output primaries. Check source-state logging before changing tone mapping or display calibration.

[general] hdr_luminance

Purpose: specifies the HDR luminance metadata policy used at ingress. Syntax: a supported input metadata token. Omitted: normal source-metadata behavior.

ValueMeaning
FOLLOW_INPUT_LLDVUse LLDV-associated incoming luminance information when available.
Capture-format tokenRequests an explicit luminance policy supported by the capture/input path.

Effect and verification: Incorrect input metadata can make otherwise correct tone mapping look wrong. Verify source EOTF and HDR metadata in the VP log first.

[renderer_alias] vp

Purpose: names the Alpha renderer's one-based renderer-selector index for shortcut handling. Syntax: positive integer. Omitted: no portable vp alias is defined.

ValueMeaning
1 or higherThe matching one-based renderer-combo position. The shipped order uses 1 for Alpha.

Effect and verification: It does not configure Alpha; it only gives a stable shortcut target. Recheck it if renderer order changes.

[renderer_alias] madvr

Purpose: names madVR's one-based renderer-selector index for shortcut handling. Syntax: positive integer. Omitted: no portable madvr alias is defined.

ValueMeaning
1 or higherThe matching one-based renderer-combo position. The supplied configuration uses 2.

Effect and verification: This alias changes neither madVR settings nor Alpha settings. Confirm the renderer list in the UI after changing installed renderers.

Queue and DirectShow

[queue] when

Purpose: gives the queue baseline a key expression that returns the queue group to root values. Syntax: a $key expression. Omitted: the baseline remains selectable only as the default.

ValueMeaning
$key=="l"Lowercase l restores the root queue policy.
Another valid key expressionUses that key chord; only valid registered key chords are accepted.

Effect and verification: The selection applies as one coherent queue policy. It is not evaluated per frame.

[queue] queue_size

Purpose: caps VP's converted-frame queue in whole frames. Syntax: integer >= 1. Omitted: VP uses its normal capacity policy.

ValueMeaning
1Minimum buffering; lowest queue latency but little resilience to a late renderer.
2 or higherMore scheduling headroom at the cost of potential buffered latency.

Effect and verification: Start from the supplied 32 baseline and use 1 only in an explicit low-latency variant. Queue diagnostics reveal saturation and recovery.

[queue] lead_frames

Purpose: adds DirectShow presentation/timestamp lead in frames. Syntax: integer 0 through 16. Omitted: the standard timing lead is used.

ValueMeaning
0No configured extra lead; sensitive to downstream timing.
1 to 16Reserve the stated lead. Higher values can improve timing headroom while adding latency.

Effect and verification: This is VP/DirectShow timing, not a renderer-private queue setting. Change it with target_frames deliberately and inspect presentation diagnostics.

[queue] target_frames

Purpose: specifies the steady converted-frame target VP tries to maintain. Syntax: integer 0 through 16. Omitted: normal target policy.

ValueMeaning
0No requested steady reserve; suitable only when the rest of the pipeline is known stable.
1 to 16Keep that many frames of converted reserve when practical; higher values trade latency for resilience.

Effect and verification: A target cannot exceed physical opportunity created by the input and renderer. Use queue telemetry rather than assuming it is always reached.

[queue] active_picture_lookahead_frames

Purpose: enables diagnostic Alpha active-picture look-ahead depth. Syntax: integer 0 through 8. Omitted: 0.

ValueMeaning
0Disable the queued-future-frame diagnostic preview.
1 to 8Analyze up to that many existing queued future frames for diagnostic decisions.

Effect and verification: It logs decision evidence; it does not itself change crop or NLS pixels. Leave it at 0 for normal viewing unless diagnosing active-picture behavior.

[queue.<variant>] when

Purpose: selects one named queue overlay. Syntax: valid key expression in a single-level, identifier-named child section. Omitted: that variant is automatic/default only.

ValueMeaning
$key=="L"Selects a named low-latency queue overlay.
Other valid key expressionSelects that overlay and retains every baseline queue key the overlay omits.

Effect and verification: A child must contain only supported queue keys. Use a distinct key and return expression so experimentation is reversible.

[directshow] video_conversion

Purpose: selects VP's source-format conversion route. Syntax: a conversion token supported by the connected DirectShow input. Omitted: VP selects its normal ingress conversion path.

ValueMeaning
V210_TO_P010Use the supported v210-to-P010 conversion path.
Another input-supported tokenRequests that conversion only when the active source format supports it.

Effect and verification: This is an ingress choice, not an Alpha scaler or output format choice. Confirm negotiated input format and formatter diagnostics in the log.

[directshow] renderer_start_stop_time_method

Purpose: selects the DirectShow start/stop timestamp policy delivered to the renderer. Syntax: a method token supported by the active DirectShow renderer path. Omitted: normal timestamp policy.

ValueMeaning
RATIONAL_RATIONALUse VP's rational timestamp method for both start and stop timestamps.
Another renderer-supported tokenRequests that explicitly supported timing policy.

Effect and verification: A timing-method change can affect cadence and handoff stability. Verify it through timestamp and renderer diagnostics, not a single subjective observation.

[directshow] frame_offset

Purpose: applies a non-negative frame-offset policy to DirectShow timing. Syntax: AUTO or a non-negative integer. Omitted: normal automatic policy.

ValueMeaning
AUTOUse VP's automatic frame-offset resolution.
0 or higherRequest that fixed offset; use only with measured timing evidence.

AUTO behavior: VP keeps the automatic resolver rather than pinning a fixed offset. Effect and verification: a fixed number is not a picture delay control; consult cadence logs before overriding AUTO.

[directshow] renderer_nominal_range

Purpose: describes the nominal input range presented to the DirectShow renderer. Syntax: a supported range policy token. Omitted: normal input-range resolution.

ValueMeaning
AUTOUse the normal input-range inference/policy.
Renderer-supported range tokenRequest the corresponding nominal input interpretation.

AUTO behavior: range is resolved from the active input/render path, not from Alpha's output_range. Effect and verification: check source-format diagnostics before treating an output-range issue as an ingress issue.

[directshow.conversion] conversion_method

Purpose: selects the implementation family used by DirectShow conversion. Syntax: one of the listed tokens. Omitted: AUTO.

ValueMeaning
AUTOChoose the normal compatible conversion implementation.
SIMDPrefer the SIMD conversion path.
OPTIMIZEDPrefer VP's optimized conversion path.
STANDARDPrefer the standard conversion path.

AUTO behavior: VP chooses its normal compatible method; it does not force a specific CPU implementation. Effect and verification: use an explicit method only for measured compatibility or performance work.

[directshow.conversion] min_core_count

Purpose: sets the minimum conversion-worker policy. Syntax: positive integer. Omitted: normal worker policy.

ValueMeaning
1Permit a single conversion worker.
2 or higherRequire at least that many workers when the conversion path can use them.

Effect and verification: More workers can consume CPU without improving a GPU- or renderer-bound pipeline. Keep it no greater than max_core_count.

[directshow.conversion] max_core_count

Purpose: caps the conversion-worker policy. Syntax: positive integer. Omitted: normal worker policy.

ValueMeaning
1Limit conversion to one worker.
2 or higherAllow up to that many workers.

Effect and verification: Treat this as a CPU budget boundary, not a quality knob. Profile actual conversion load before raising it.

[directshow.ppm] ppm

Purpose: applies one source-timing correction in parts per million across cadences. Syntax: AUTO or an integer from -1,000,000 through 1,000,000. Omitted: automatic correction.

ValueMeaning
AUTOUse the automatic calibration sentinel.
Negative integerApply a measured negative source-rate correction.
0Apply no fixed correction.
Positive integerApply a measured positive source-rate correction.

AUTO behavior: VP retains automatic timing calibration instead of a fixed PPM value. Effect and verification: use a fixed correction only from repeatable timing evidence.

[shortcuts] render.<index>

Purpose: binds a shortcut to the one-based renderer selector index. Syntax: key name on the right; positive renderer index in the key name. Omitted: no direct renderer shortcut.

ValueMeaning
render.1: APress A to select renderer index 1.
render.2: MPress M to select renderer index 2.

Effect and verification: Indices refer to the actual renderer UI order. The aliases above make a checked-in configuration easier to read, but the shortcut is still index-based.

VideoProcessor Renderer (Alpha)

These settings affect only VideoProcessor Renderer (Alpha). Alpha feeds the bundled libplacebo renderer, but this page names only the values VP accepts. A root [vprenderer] is a baseline. If there is no root, the first named [vprenderer.name] section is the baseline and later names inherit it.

[vprenderer] when

Purpose: supplies the baseline-return expression for the Alpha display group. Syntax: valid key expression. Omitted: the root remains the ordinary baseline.

ValueMeaning
$key=="F4"F4 restores the root Alpha baseline.
Another valid key expressionUses that registered key to return to the root values.

Effect and verification: This changes profile selection only; it does not edit the file or persist across restart.

[vprenderer] quality

Purpose: chooses Alpha's libplacebo render-parameter preset. Syntax: fast, balanced, or high. Omitted: high.

How this interacts with AUTO: Alpha copies this preset first, then applies the other [vprenderer] settings. For the renderer options below, AUTO means “retain the copied preset value”; it is not a per-frame algorithm search. A non-AUTO setting overrides only its own part of the preset. The concrete selections below are for the bundled libplacebo 7.360.1 build used by Alpha today.

ValuePreset selectedMeaning and trade-off
fastpl_render_fast_paramsMinimal renderer configuration. It leaves the advanced up/downscalers, sigmoidization, peak detection, dithering, and debanding disabled. Scaling therefore falls back to libplacebo's inexpensive built-in sampling (bilinear or nearest-neighbour, according to the GPU path). Use it to recover GPU headroom; it is deliberately not a quality-equivalent alternative.

[vprenderer] tone_mapping

Purpose: selects HDR-to-target luminance mapping before output encoding. Syntax: one listed token. Omitted: AUTO.

ValueMeaning and trade-off
AUTOKeep the bundled libplacebo color-map default; VP does not force a named curve.
splineSmooth highlight roll-off with a natural overall contrast balance; a good conservative HDR-to-SDR starting point.
bt2390BT.2390-style highlight roll-off; useful when a standards-oriented, gentler knee is preferred.
st2094-40Use ST.2094-40-oriented dynamic metadata behavior when compatible metadata is present; content-dependent results can vary.
reinhardSimple photographic compression; can retain highlight structure but may look flatter than spline on some material.

AUTO behavior: Alpha leaves pl_color_map_params at the bundled libplacebo default rather than selecting a VP curve. Effect and verification: tone mapping changes highlight/contrast behavior and can make dynamic peak analysis relevant; Alpha's settings log reports the resolved mapping.

[vprenderer] gamut_mapping

Purpose: controls how colors outside the target gamut are brought into it. Syntax: one listed token. Omitted: AUTO.

ValueMeaning and trade-off
AUTOKeep libplacebo's default gamut behavior.
perceptualCompresses out-of-gamut colors with the aim of preserving overall color relationships; a sensible general starting point.

AUTO behavior: VP leaves the bundled libplacebo gamut default intact. Effect and verification: choose it together with sdr_target_primaries and any calibration LUT; the Alpha settings log reports the resolved gamut mapper.

[vprenderer] peak_detection

Shader groups and NLS

Shader groups are independent from Alpha color profiles. A root [shader.group] is an explicit off/baseline selection. A child is one shader member. For a single group, one matching member is selected; for type: multi, all matching children compose in stage/order sequence.

[shader.<group>] type

Purpose: chooses whether a group's matching children are exclusive or composited. Syntax: single or multi. Omitted: single.

ValueMeaning
singleSelect one matching member; use for alternate NLS modes.
multiCompose every matching member in deterministic stage/order sequence; use for cleanup stacks.

Effect and verification: Use multi only when the effects are intended to stack. A root with no child is the explicit off state.

[shader.<group>] when

Purpose: selects the group's empty root/baseline. Syntax: valid key or source-state expression. Omitted: root is the normal baseline.

ValueMeaning
$key=="n"Selects the empty NLS root, turning that group's NLS effect off.
$key=="d"Selects an empty cleanup root.

Effect and verification: An empty root is not an error; it is the reversible way to clear a selected group.

[shader.<group>.<member>] when

Purpose: selects a shader member. Syntax: valid key or source-state expression. Omitted: the member is not automatically selected.

ValueMeaning
$key=="Shift+n"Select one named NLS member.
$transfer=="SDR"Select/compose a member when the source state matches.

Effect and verification: Source-state rules are reevaluated on source state changes/rebuilds, not every frame. Avoid key collisions within an exclusive group.

[shader.<group>.<member>] shader_type

Purpose: identifies the shader member's contract. Syntax: nls or custom. Omitted: required for a member.

ValueMeaning
nlsUse VP's nonlinear-stretch parameter contract.
customUse the named backend shader file without NLS-specific interpretation.

Effect and verification: An unknown type invalidates the member. Keep NLS controls only on an nls member.

[shader.<group>.<member>] label

Purpose: gives a selected shader member a human-readable UI/log label. Syntax: non-empty text. Omitted: no custom label.

ValueMeaning
Nonlinear StretchDescribes the standard NLS member.
Light DenoiseDescribes a custom cleanup member.

Effect and verification: Labels do not alter shader behavior; choose a name that distinguishes the actual effect and stage.

[shader.<group>.<member>] stage

Purpose: positions a shader before or after renderer resizing. Syntax: pre_resize or post_resize. Omitted: pre_resize.

ValueMeaning
pre_resizeRun on the source-sized image before resizing; suitable for many cleanup effects.
post_resizeRun after resizing; suitable for output-space sharpening or finishing.

Effect and verification: The same shader can look materially different at each stage. Choose stage before tuning strength.

[shader.<group>.<member>] order

Purpose: orders composed shader members within one stage. Syntax: non-negative integer. Omitted: 0.

ValueMeaning
0Earliest/default order in its stage.
10, 20, ...Spaced order values that make a multi-member stack easy to review and extend.

Effect and verification: Use unique values within a stage. The supplied cleanup stack puts deband/denoise before a post-resize sharpen.

[shader.<group>.<member>] hlsl_file

Purpose: names the madVR/HLSL implementation for this logical member. Syntax: a shader file path/name available to the configured shader loader. Omitted: madVR ignores this logical member if no HLSL implementation exists.

ValueMeaning
NLS.hlslHLSL implementation of the supplied NLS member.
Debanding mild.hlslHLSL implementation of a custom cleanup member.

Effect and verification: A missing/unreadable file invalidates that backend member. It does not make a GLSL implementation usable by madVR.

[shader.<group>.<member>] glsl_file

Purpose: names the Alpha/GLSL implementation for this logical member. Syntax: a GLSL shader file path/name available to Alpha. Omitted: Alpha ignores this logical member if no GLSL implementation exists.

ValueMeaning
NLS.glslGLSL implementation of the supplied NLS member.
Another available GLSL fileUse that Alpha implementation for the logical member.

Effect and verification: Keep HLSL and GLSL entries together only when they represent the same intended effect. Alpha logs shader loading/compilation failures.

[shader.<group>.<member>] geometry

Purpose: chooses the NLS geometry mode. Syntax: an NLS geometry token understood by the installed NLS shader. Omitted: the shader's default geometry.

ValueMeaning
classicStandard nonlinear-stretch geometry.
protectedGeometry intended for use with centre protection.

Effect and verification: Treat geometry and center_protection as a pair. Use the shipped names unless the installed NLS shader explicitly supports another mode.

[shader.<group>.<member>] strength

Purpose: sets NLS intensity. Syntax: finite numeric shader parameter. Omitted: shader default.

ValueMeaning
0No configured nonlinear-stretch intensity.
1.0Standard supplied NLS intensity.
Other finite numberShader-specific intensity; test carefully for geometric distortion.

Effect and verification: Strength is not a color sharpness control. Test with geometry and titles, then return to the empty NLS root to compare.

[shader.<group>.<member>] center_protection

Purpose: preserves the central image region during protected NLS. Syntax: finite numeric shader parameter. Omitted: shader default/no explicit protection.

ValueMeaning
0No configured central protection.
0.35Supplied protected-NLS value; preserves a meaningful central region.
Other finite numberShader-specific protection amount; tune with a geometry pattern.

Effect and verification: Higher protection generally limits centre distortion but leaves less room for edge stretch. It matters primarily with protected geometry.

[shader.<group>.<member>] curve

Purpose: shapes the NLS falloff curve. Syntax: finite numeric shader parameter. Omitted: shader default.

ValueMeaning
2.0Supplied standard curve shape.
Lower finite numberMoves the stretch transition more gradually, subject to shader behavior.
Higher finite numberConcentrates the transition more strongly; inspect edge distortion.

Effect and verification: Curve and strength interact. Change one at a time and compare against an unprocessed frame.

[shader.<group>.<member>] quality

Purpose: selects the NLS shader quality mode. Syntax: a quality token understood by the installed NLS shader. Omitted: shader default.

ValueMeaning
highSupplied high-quality NLS mode; use when GPU headroom allows.
Another supported quality tokenUse only when the corresponding shader implementation documents it.

Effect and verification: This is separate from Alpha's global quality. Watch shader compilation and render timing after changing it.

[shader.<group>.<member>] tolerance_percent

Purpose: sets NLS aspect-tolerance threshold. Syntax: number 0 through 50 percent. Omitted: 5 percent.

ValueMeaning
0Require an exact aspect match before the rule is considered suitable.
5Supplied conservative tolerance.
Above 5 through 50Allow progressively larger aspect deviation; risk applying NLS where it does not fit.

Effect and verification: This is a suitability guard, not a scale factor. Keep it modest unless actual input aspect variation demands more.

Refresh event actions

[actions.<name>] scope

Purpose: limits an action to a renderer scope. Syntax: vprenderer, directshow, or *. Omitted: vprenderer.

ValueMeaning
vprendererRun only for Alpha refresh transitions.
directshowRun only for DirectShow refresh transitions.
*Run for either supported scope.

Effect and verification: Choose the narrowest scope that matches the external command. The default prevents Alpha-specific automation from running for other renderer paths.

[actions.<name>] on

Purpose: lists committed refresh events that can trigger an action. Syntax: comma-separated supported event tokens. Omitted: required for an actionable section.

ValueMeaning
refresh.appliedRun after the requested refresh has been applied.
refresh.confirmedRun after VP confirms the refresh transition.
refresh.restoredRun after restoration of the previous refresh state.

Effect and verification: Actions run after committed transitions, never per frame. Combine events only when the command is safe to run for each one.

[actions.<name>] when

Purpose: narrows an action to a refresh condition. Syntax: expression using $actual_refresh, $requested_refresh, and $previous_refresh. Omitted: the action applies to every listed event in scope.

ValueMeaning
$actual_refresh<=30Run only after a confirmed/applied rate at or below 30 Hz.
$actual_refresh>=50Run only for video-rate output at or above 50 Hz.

Effect and verification: Keep the expression about the committed transition. The log records event/action decisions and is the evidence that a condition matched.

[actions.<name>] run

Purpose: supplies the program and arguments run by an accepted event action. Syntax: an .exe, .bat, or .cmd path followed by optional arguments. Omitted: no runnable action.

ValueMeaning
C:\Videoprocessor\audio\audio_delay.bat 100Run the named batch file with 100 as its argument.
Absolute executable/batch path plus argumentsRun that command only after the configured event and condition pass.

Effect and verification: Keep actions idempotent and short-lived. A path that does not end in a supported executable/batch extension is rejected by the configuration reader.

Practical starting points

Conservative SDR input to SDR output

[vprenderer.rec709]
when: $key=="F4"
sdr_target_nits: 100
quality: high
tone_mapping: AUTO
gamut_mapping: AUTO
sdr_target_primaries: REC709
output_range: AUTO
output_gamma: AUTO

Leave input transfer, scalers, deband, and dithering on AUTO until an observed source/output issue requires an override.

HDR input to a calibrated SDR/projector target

[vprenderer.projector]
when: $key=="F6"
sdr_target_nits: 100
sdr_black_nits: AUTO
tone_mapping: spline
gamut_mapping: perceptual
peak_detection: AUTO
contrast_recovery: AUTO
sdr_target_primaries: REC709
output_gamma: bt1886

Use the target luminance, black, transfer, and primaries measured for the projector/LUT. The example is a starting point, not a calibration prescription.

SDR BT.2020 display profile

[vprenderer.bt2020]
when: $key=="F5"
sdr_target_primaries: BT2020
report_bt2020_to_display: true
output_range: AUTO
output_gamma: AUTO

Enable this only for a display chain that is intentionally calibrated and signaled for SDR BT.2020. The F5 overlay inherits the named baseline values it does not repeat.

Scaling a lower-resolution source

[vprenderer]
quality: high
upscaler: ewa_lanczos
downscaler: AUTO
deband: AUTO
dithering: AUTO

Compare the chosen upscaler only while the source is enlarged. For native-size content, leave it at AUTO; a visible difference is likely coming from another stage.

NLS versus renderer scaling

Alpha's upscaler and downscaler resample pixels. An NLS shader changes presentation geometry before/after resizing according to its configured stage. Use the empty shader root to turn NLS off for an honest scaler comparison.

Profile, viewport, and queue together

[queue.low_latency]
when: $key=="L"
queue_size: 1
target_frames: 1

[vprenderer.bt2020]
when: $key=="F5"
sdr_target_primaries: BT2020
report_bt2020_to_display: true

[vprenderer.viewport.scope]
when: $key=="F2"
screen_aspect: 2.35:1
automatic_crop: true

These are independent selections: L changes queue policy, F5 changes Alpha color/output policy, and F2 changes viewport geometry. Their effects compose but do not overwrite one another.

SymptomLikely causeSafe check
VP rejects the file at startup.Unknown key, wrong section, duplicate key, malformed Boolean, or out-of-range number.Read the first configuration error in vp_debug.log; restore the documented spelling and value rather than adding aliases.
AUTO does not look like a named mode.AUTO deliberately leaves a renderer/default resolver in control.Use the Alpha settings log to see the resolved mapper/scaler/presentation state, then test one explicit value only if needed.
No visible scaler change.The content is native-sized, a viewport/crop changed instead, or another renderer is active.Confirm Alpha is selected, use a known upscale/downscale case, and compare with the empty shader root.
