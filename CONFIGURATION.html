VideoProcessor configuration reference

Application configuration | Built-in renderer configuration

Application configuration

VideoProcessor.cfg is an optional UTF-8 text file searched first beside the executable, then up to two parent directories, with the application's working directory as a fallback. It uses INI-style sections and key=value entries. Blank lines and lines beginning with # are ignored.

The shipped file is a conservative sample with common [command_line], [logging], and [queue_recovery] settings. The optional [display_refresh_rate_override], [shaders], [p010_conversion], and [ppm_correction] sections can be added when needed.

VideoProcessor.cfg is the normal single configuration file for application, capture, shader, built-in renderer, profile, hotkey, and completed-event settings.

Strict ownership remains enforced inside the combined file: application settings are read at startup, while renderer profile and event expressions may change only renderer-owned settings. Capture, queue, conversion, and other application keys cannot be placed in renderer profiles.

Command-line arguments are applied after configuration values, allowing a shortcut or script to override matching settings.

Use /config "path\VideoProcessor.cfg" to select a different complete configuration for one process. Relative paths are resolved from the process working directory, and an explicitly selected file must exist. The --config and -config spellings are equivalent; /config=path is also accepted.

[logging]

VideoProcessor keeps the active debug log at logs\vp_debug.log beneath the directory containing the main executable. VP does not create the logs directory. If the directory is absent or unwritable, logging is disabled for that process and no fallback log is written. At process startup, a non-empty prior active log is archived with a sortable name such as vp_debug.20260727-153045.log, then older matching archives are pruned. Rotation errors are non-fatal and are recorded when the configured destination remains writable.

KeyType and defaultEffect
debug_log_retentionInteger 1-100; default 10Total VP debug-log files to retain, including the active log. The value is read once at startup. Omitted, invalid, zero, duplicate, or out-of-range values resolve to 10. A value of 1 retains only the active log; zero never disables rotation. Files that do not exactly match VP's archive naming contract are never pruned.
[logging]
debug_log_retention=10

[queue_recovery]

These settings control the automatic queue-only recovery safeguard. The raw and converted queues are evaluated independently; the percentage is not applied to their combined display total. If either queue reaches the configured high-water mark, VideoProcessor waits the configured delay and then flushes/re-primes the live source queue without rebuilding the renderer graph.

KeyType and defaultEffect
reset_after_render_restart_secondsPositive integer; default 5Delay before the automatic recovery reset after startup/restart or a high-water event.
reset_queue_too_large_percentInteger 1-100; default 75Per-queue high-water threshold that schedules recovery.
[queue_recovery]
reset_after_render_restart_seconds=5
reset_queue_too_large_percent=75

[shortcuts]

Keyboard shortcuts are optional. If this section, an individual key, or the entire configuration file is absent, VideoProcessor uses its built-in defaults. Modifier names are case-insensitive. A lowercase letter is unmodified (v); an uppercase letter adds Shift (V means Shift+V).

Supported modifiers are Ctrl, Alt, and Shift. Keys may be a letter, a number, F1 through F24, Escape, or Enter. Invalid or duplicate bindings fall back to the built-in binding for fixed commands.

Dynamic render.N entries select the 1-based renderer-combo entry and perform the same controlled renderer restart as a UI selection. The sorted, machine-specific order is logged at startup as Renderer order: render.N = <name>. An unavailable index is ignored safely.

LLDV

DeckLink does not expose the HDMI Dolby Vision VSIF. The newlldv option is a heuristic, not definitive detection.

With newlldv=true, VideoProcessor treats stable BT.2020 + SDR + no static HDR metadata as LLDV only when both hdr_colorspace=FOLLOW_INPUT_LLDV and hdr_luminance=FOLLOW_INPUT_LLDV are selected. After a 1.5-second confirmation it switches output to PQ and supplies synthetic HDR metadata.

Leave newlldv disabled for legacy behavior or whenever genuine BT.2020 SDR could be mistaken for LLDV.

[display_refresh_rate_override] (optional)

Use this section when the automatic display-rate measurement is known to be wrong. Keys are nominal input refresh rates, matching the [ppm_correction] format; values are exact display rates or AUTO. A truncated nominal key is preferred (for example, 23 for 23.976 Hz); otherwise a key within 0.5 Hz is used. An exact rate replaces automatic display timing, is shown with * in the OSD, and is explicitly identified in the log. AUTO explicitly keeps normal automatic measurement for that nominal rate.

[shaders] (optional)

This section installs external Direct3D 9 HLSL directly into the selected renderer's GPU pipeline when that renderer supports external shaders. It does not add a CPU conversion or GPU readback. The named automatic rules in rules are checked from left to right and the first matching rule wins. If nothing matches, default=none leaves shaders off. Rules are reevaluated after every full renderer restart using VP's effective EOTF and input refresh rate. Detected LLDV is treated as HDR because its effective EOTF is PQ. A rule may instead be marked manual=true and assigned its own shortcut.

Manual nonlinear stretch example

This keeps final aspect/zoom control in madVR. Shift+N arms VP's pre-resize mapping and N turns it off. NLS declares its target aspect to madVR so madVR's zoom policy can fit the mapped image correctly; entering or leaving that output contract can therefore perform one controlled renderer restart. While NLS remains armed, confirmed content-aspect changes are restart-free: matching Scope content uses linear active-rectangle passthrough and narrower IMAX/16:9 content uses nonlinear mapping against the same output contract. Active-picture geometry is sampled on an approximately 80 ms cadence (normalized for 23.976 through 60 fps). Initial lock requires four matching observations. A clear, symmetric bar transition withdraws stale geometry after its first observation and commits the new geometry after two matches; ambiguous or asymmetric changes require five matches. Black, fade, and otherwise unavailable observations preserve the last stable mapping. The dialog polls geometry generation every 100 ms, so a confirmed transition updates NLS without waiting for the one-second status timer or restarting the renderer. F2 selects the Scope (2.35:1) target and F3 selects the Normal (16:9) target; those screen-profile changes are restart-free and refresh only the NLS target. Therefore use F2 then Shift+N for 16:9-to-scope stretch, and F3 then Shift+N for 4:3-to-16:9 stretch. The armed request persists through renderer restarts and waits for fresh geometry from the new renderer generation before reinstalling the mapping. strength controls the total correction, curve controls how progressively it changes across the picture, and stretch_ratio describes the target expansion. geometry=classic uses the established SickGreg/SuperView-style power curve and is the compatibility default when the key is omitted. geometry=protected holds the central center_protection fraction at its original apparent width and uses a smooth monotonic transition to move more distortion toward the sides; accepted values are 0.0-0.45 and 0.35 protects the central 35% of the picture. quality selects single-sample bilinear Low, four-tap positive-filter Medium, six-tap anti-ringing Lanczos-3 High, or eight-tap anti-ringing Lanczos-4 Very High reconstruction. High is the recommended sharp setting; Medium is the conservative lower-cost setting.

[shaders]
enabled=true
rules=nls,nls_off,broadcast_sdr,movies_24
default=none

[shaders.nls]
label=Nonlinear Stretch
manual=true
shortcut=N
output_aspect_ratio=2.35
nls_target_aspect_ratio=2.35
aspect_tolerance_percent=5
aspect_direction=any
active_aspect_min=1.0
pre_resize_1=Shaders\NLS.hlsl
param_strength=1.0
param_geometry=protected
param_center_protection=0.35
param_curve=2.0
param_stretch_ratio=1.321875
param_quality=medium

[shaders.nls_off]
label=NLS Off
manual=true
shortcut=n
output_aspect_ratio=native
none=true

Relative shader paths are resolved from the directory containing VideoProcessor.cfg. The OSD displays the selected rule and every successfully installed shader, and automatically resizes to fit the active chain. The original flat profile, pre_resize_N, and post_resize_N format remains accepted when rules is absent.

Shaders execute GPU code inside the selected renderer. A compilation failure disables that entire stage and is reported in the log. Expensive or defective shaders can cause dropped frames or a GPU device reset. HDR/color shaders must be written for the color domain presented by the renderer; do not combine an HDR-to-SDR shader with renderer tone mapping unless the chain is intentionally designed that way.

[ppm_correction] (optional)

This section provides per-refresh-rate timing corrections for rational timing modes. Keys are truncated refresh rates; values are PPM corrections or AUTO. If the section is absent or has no valid matching entry, VideoProcessor enables automatic PPM calibration with an initial zero correction.

[ppm_correction]
59=5
29=AUTO
23=0
  • 59 matches 59.94 Hz, 29 matches 29.97 Hz, and 23 matches 23.976 Hz.
  • Positive PPM makes the stream faster; negative PPM makes it slower.
  • AUTO enables automatic calibration for that refresh rate.

Built-in renderer configuration

The optional built-in libplacebo renderer is configured in the same VideoProcessor.cfg. Select it with renderer: VideoProcessor Renderer (Alpha) in [command_line]. Its complete optional plugin pack belongs in a libplacebo directory beside VideoProcessor.exe; if it is unavailable, the application starts normally without listing that renderer.

Renderer entries use the canonical key: value syntax. Existing key=value entries remain readable. The renderer always produces SDR output; HDR, HLG, and detected LLDV input is tone-mapped using the effective input colorspace and mastering metadata.

Quick start: how renderer configuration fits together

The renderer is a separate configuration domain inside the same file. Application sections such as [command_line], capture, queue, shader, and conversion settings start VP. Renderer sections decide how the already-captured frames are processed and displayed. Renderer profiles cannot modify application-owned settings.

  1. Choose the Alpha renderer in [command_line].
  2. Set safe, always-on values in [display] and [general].
  3. Declare all four required profile groups: input, scaling, display, and viewport.
  4. Define named profiles in each group. Use source rules for automatic input/scaling behavior and $key for manual display/viewport behavior.
  5. VP resolves one profile per group, applies the combined result, then records a successful manual selection in VideoProcessor.state.
[command_line]
renderer: VideoProcessor Renderer (Alpha)

[display]
quality: high
sdr_target_nits: 100
sdr_target_primaries: REC709

[general]
switch_refresh_rate: true
persist_profile_selection: true

Profiles and hotkeys

Profiles are independent groups: input, scaling, display, and viewport. Declare each group in [profile_groups.<group>], then define settings in [profiles.<group>.<name>]. A profile's when expression can use source metadata or $key. The same key may select profiles in multiple groups; no profile may write a setting owned by a different group or by the application.

GroupMay overrideTypical selector
inputtone_mapping, gamut_mapping, peak_detection, contrast_recovery, sdr_input_transferSource transfer, primaries, HDR metadata
scalingquality, upscaler, downscaler, sigmoid, deband_strength, ditheringResolution or frame size
displayTarget nits/black, presentation/range/gamma, target primaries, BT.2020 signalling, and lut plus its reference fieldsManual display/calibration hotkey
viewportmode, scope aspect, subtitle-fit, hold, and paddingManual Normal/Scope hotkey

Each group requires profiles: and default:. The default is a listed profile or auto. persist_profile_selection: may be set per group. A group-level when: is a reset chord: it returns that group to automatic selection without changing other groups.

[profile_groups.display]
profiles: rec709,bt2020
default: auto
when: $key=="F4"

[profiles.display.rec709]
when: $key=="F5" || $key=="Ctrl+F10"
sdr_target_primaries: REC709
report_bt2020_to_display: false

[profiles.display.bt2020]
when: $key=="F6" || $key=="Ctrl+F9"
sdr_target_primaries: BT2020
report_bt2020_to_display: true

The selected manual profiles are stored alongside the configuration in VideoProcessor.state, and only after a successful renderer application. A failed change leaves both the active renderer and the saved selection intact.

Automatic rules and expression language

A profile without when: is selectable as the configured default or persisted manual choice. An automatic profile uses a source condition; the highest matching priority: wins (default 0), with declared profile order making a remaining tie deterministic. Strictness and safe changes

Unified configuration rejects duplicate keys, unknown sections, missing listed profiles, orphan profile sections, invalid defaults, unknown variables, malformed expressions, unsupported values, and a setting placed in the wrong profile group. Application settings such as capture, queues, conversion, and shaders remain startup-only and cannot be changed by a renderer profile. Legacy display-rule syntax is not part of the unified model.

Changes are transactional. VP first resolves the full effective settings, then applies/rebuilds the renderer as needed. It persists a manual selection and runs completed-event actions only after the change succeeds. If application fails, the prior renderer, state, and selection remain in effect.

Completed-event actions

Optional [event_actions] entries run only after a successful applied, confirmed, or restored renderer transition. The section lists action names; each action requires on:, when:, and program:. arguments:, working_directory:, and a 0–30 second delay_seconds: are optional. Without a per-action delay, the value from [general] is used.

[event_actions]
actions: audio_delay_film

[event_actions.audio_delay_film]
on: refresh.applied,refresh.confirmed
when: $actual_refresh==23.976 || $actual_refresh==24
program: C:\Videoprocessor\audio\audio_delay.bat
arguments: 315

Supported events are refresh.applied, refresh.confirmed, and refresh.restored. Actions are not profile selectors and cannot change renderer settings. Failed or unsupported refresh changes run no action.

Troubleshooting renderer profiles

SymptomCheck
VP will not start with the Alpha rendererRead the configuration error. Unified configuration fails closed on a misspelled section/key, invalid setting value, missing listed profile, or invalid expression.
A hotkey does nothingVerify the VP window has focus, the chord is quoted exactly, and it is not assigned to two profiles in the same group. Check C:\logs\vp_debug.log for registered profile bindings.
An automatic rule never winsVerify the captured metadata in the debug log, then compare its transfer/primaries/raster values with the rule. Raise priority: only when two matching profiles genuinely need ordering.
The wrong profile reappears after restartManual selections persist by default. Use the group reset chord, set persist_profile_selection: false for that group, or remove the relevant entry from VideoProcessor.state while VP is stopped.
Display or colour changes failVP keeps the last successful renderer state. Inspect the log for the rejected output contract or unsupported display capability; do not assume the profile name alone proves a setting applied.
