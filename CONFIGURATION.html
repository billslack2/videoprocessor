VideoProcessor configuration reference

The shipped VideoProcessor.cfg is one strict, startup-read configuration file. This reference describes the supported public settings for capture, DirectShow, the VideoProcessor Renderer (Alpha), shader selection, and refresh actions. It is deliberately value-level: use it to decide what a setting changes before editing your working configuration.

Start conservatively. Copy only the setting that solves a known problem, keep your prior value in a comment, and change calibration-related values only when they match the display or LUT you actually use. Configuration is read at startup; a renderer rebuild may apply a newly selected Alpha or viewport variant, but editing the file itself requires restarting VideoProcessor.
Strict syntax matters. A malformed public setting is rejected during startup validation or reported in vp_debug.log. Names are case-insensitive, but the spelling and section shown here are the supported contract. Every AUTO entry below names either its exact resolved value or the specific source/hardware condition that determines it; it never means "try every upstream library option."

How to read and compose the file

Sections own settings. A root section is the normal baseline. A named child section is a variant that inherits its group's baseline and replaces only the keys it declares. A matching when expression selects the variant in memory. Selecting a root expression returns that group to its baseline; it does not retain keys from the previous variant. Selections are process-local and disappear when VP exits.

Configuration locationWhat it controlsSelection model
[general], [directshow]Application and input-pipeline startup policy.Read at startup; no profile inheritance.
[queue], [queue.name]VP queue capacity and timing policy.Root or one named selected overlay.
[vprenderer], [vprenderer.name]Alpha's color, scaling, output, and refresh policy.Root or first named section is the baseline; later named sections overlay it.
[vprenderer.viewport], [vprenderer.viewport.name]Alpha presentation geometry and subtitle placement.Independent root/variant selection.
[shader.group], [shader.group.member]Renderer-specific shader selections.Single groups select one member; multi groups compose matching members.

Conditional selection contract (when)

when is a strict, side-effect-free condition. It selects a root or named configuration variant in memory; it does not change the file, create a hotkey by itself, or persist a selection after VP exits. Use ${variable} as the single public variable form everywhere: in when it reads a value for comparison, and in an action's run arguments it passes that event-bound value to the command. The same expression grammar is shared where when is supported, but each owner limits the variables that it accepts.

FormContract
Text comparison${<text-variable>} == <value> or !=. Text values are case-insensitive except a keyboard shortcut.
Numeric comparison${<number-variable>} == <number>, !=, <, <=, >, or >=. Equality may use a numeric range such as <minimum>-<maximum>.
Boolean comparison${<boolean-variable>}, !${<boolean-variable>}, or an explicit comparison to true or false.
CompositionCombine complete comparisons with && (and), || (or), ! (not), and parentheses. A comparison must name a supported variable.
Manual key selection${key}=="<shortcut>" only. A keyboard shortcut is one key with optional modifiers, written in VP's accelerator spelling. It must be non-empty, quoted, and unique within its group. It is case-sensitive, so an uppercase letter denotes Shift.
OwnerVariables it may use
Queue, Alpha display, and viewport variants; shader rulesSource text: eotf, transfer, colorspace, primaries, format, scan, resolution; source Booleans: hdr_metadata, interlaced; source numbers: source_rate, cadence, width, height; or key.
Root reset selection for queue, Alpha display, and viewportkey only. Omit the root when when no direct key is needed to return to that baseline.
Refresh actionevent, event_reason, actual_refresh, requested_refresh, and previous_refresh.
Committed source, profile, or renderer actionevent, event_reason, every source variable above, current profile.input, profile.scaling, profile.display, profile.viewport, and profile.queue, plus the matching previous.<source-variable> and previous_profile.<group> forms.

Matching and precedence: source-state conditions are reevaluated when the relevant source/profile state changes, not for every video frame. A manual key selection applies to its own group only; queue, display, viewport, and shader groups remain independent. If several automatic variants match, VP selects the supported highest-priority/most-specific candidate for that group and records the result in diagnostics.

Startup, capture, and renderer selection

[general] capture_device

Purpose: chooses the capture device VP opens at startup. Syntax: the exact device name displayed by VP or its capture backend. Omitted: VP uses its normal device-selection path.

ValueMeaning
Exact device nameRequests that installed capture device; retain punctuation and any adapter suffix.
OmittedDoes not force a device and lets the normal startup choice apply.

Effect and verification: This is a startup-only choice. Check the startup portion of vp_debug.log for the selected device; an unavailable name is not a portable preset.

[general] renderer

Purpose: selects the startup output renderer. Syntax: exact renderer name from VP's renderer selector. Omitted: VP keeps its normal renderer selection.

ValueMeaning
VideoProcessor Renderer (Alpha)Starts the built-in libplacebo-based Alpha renderer; the [vprenderer] settings in this document apply.
An installed renderer nameStarts that renderer. Its own settings, capabilities, and latency differ.

Effect and verification: Startup-only. The selected renderer is logged and visible in the VP UI. Do not assume an Alpha profile applies the same setting to a different renderer.

[general] hide_legacy_renderers

Purpose: curates the DirectShow renderer picker by server location. Syntax: Boolean; default true. Omitted: Windows System32-hosted DirectShow registrations stay hidden.

Effect and verification: This is a picker policy, not a capability claim. Set false only for troubleshooting to expose System32-hosted candidates; non-System32 candidates and the independent DeckLink exclusion are unaffected. Check the discovery log for each candidate's CLSID, server path, and decision.

[general] fullscreen

Purpose: requests fullscreen startup. Syntax: true or false. Omitted: uses VP's normal window startup behavior.

ValueMeaning
trueRequest fullscreen at startup.
falseStart without requesting fullscreen.

Effect and verification: Fullscreen transitions can recreate renderer resources. Confirm the final output mode in the UI and log rather than assuming the request was accepted by every display path.

[general] fullscreen_monitor_name

Purpose: selects the active monitor that receives VP's fullscreen host. Syntax: an exact, case-insensitive Windows monitor friendly name, for example EPSON PJ. Surrounding whitespace is ignored. Omitted: VP uses its existing monitor-nearest-to-main-window behavior.

Effect and verification: This affects only fullscreen host creation for Alpha and DirectShow; it never enables fullscreen or changes Windows display settings. If the named monitor is disconnected, unavailable, or ambiguous, VP starts normally on its existing fallback monitor and records configured monitor unavailable (or the ambiguity reason) in vp_debug.log.

[general] fullscreen_monitor_session_mode

Purpose: optionally creates a temporary target-only Windows display session before fullscreen VP starts. Values: existing (default) or target-only. Omitted: VP never changes display topology.

Use with caution: target-only requires one exact fullscreen_monitor_name. VP durably records the current topology in VideoProcessor.state, activates only that connected target, and temporarily disables every other monitor. Fullscreen-off and normal exit restore the recorded modes, positions, primary display, and activation state. Selection, validation, or activation failure leaves the existing topology in place and uses normal VP-0094 fallback behavior.

Crash recovery: a hard termination cannot run normal cleanup. Run VideoProcessor.exe /fix_display to restore a pending display transaction and exit without launching VP. Ordinary startup also restores a stale transaction before doing anything else. The recovery record is retained until restoration succeeds.

[general] windowed_fullscreen_mode

Purpose: chooses VP's borderless/windowed fullscreen mode when fullscreen is requested. Syntax: a Boolean. Omitted: leaves the normal fullscreen mode unchanged.

ValueMeaning
truePrefer VP's windowed fullscreen path.
falseDo not request the windowed fullscreen path.

Effect and verification: This is an output-window policy, not an Alpha presentation setting. Test it with the actual display and renderer because compositor behavior is platform dependent.

[general] startminimized

Purpose: controls whether the VP control window starts minimized. Syntax: a Boolean. Omitted: normal UI startup.

ValueMeaning
trueStart the control window minimized while the configured output continues starting.
falseShow the normal control window.

Effect and verification: It does not disable capture, rendering, or diagnostics; it changes only initial UI visibility.

[general] scene_detect

Purpose: enables VP's scene-detection policy where the active renderer and pipeline support it. Syntax: a Boolean. Omitted: leaves the normal pipeline default.

ValueMeaning
trueAllow scene-aware cadence and related logic to run.
falseDo not request scene detection.

Effect and verification: Scene analysis can add work and log activity but is not a substitute for renderer queue policy. Inspect scene/cadence messages in vp_debug.log.

[general] hdr_colorspace

Purpose: specifies the HDR input colorspace metadata policy presented by DirectShow. Syntax: a supported capture/input metadata token. Omitted: leaves input metadata policy at its normal resolver behavior.

ValueMeaning
FOLLOW_INPUT_LLDVUse the incoming LLDV-associated colorspace interpretation when the source supplies it.
Capture-format tokenRequests that explicit input metadata policy; use only a value supported by the connected capture path.

Effect and verification: This describes input metadata, not the Alpha output primaries. Check source-state logging before changing tone mapping or display calibration.

[general] hdr_luminance

Purpose: specifies the HDR luminance metadata policy used at ingress. Syntax: a supported input metadata token. Omitted: normal source-metadata behavior.

ValueMeaning
FOLLOW_INPUT_LLDVUse LLDV-associated incoming luminance information when available.
Capture-format tokenRequests an explicit luminance policy supported by the capture/input path.

Effect and verification: Incorrect input metadata can make otherwise correct tone mapping look wrong. Verify source EOTF and HDR metadata in the VP log first.

[renderer_alias] <name>

Purpose: gives a locally installed non-Alpha renderer a portable action/shortcut name. Syntax: an identifier and its positive one-based renderer-selector index. Omitted: no alias is defined; actions can still use vprenderer for the built-in Alpha renderer or * for every renderer.

ValueMeaning
1 or higherThe matching one-based position in VP's renderer selector for this local installation.

Effect and verification: An alias does not configure the renderer. An action with renderer: <name> runs only while this selector position is active. Check the startup log's render.N entries after changing renderer installations or order. Do not define vprenderer as an alias: VP identifies its built-in Alpha backend directly.

Queue and DirectShow

[queue] when

Purpose: optionally provides a direct selector for the root queue baseline. Syntax: ${key}=="<shortcut>" only; see the conditional selection contract. Omitted: the root is still the normal queue baseline but has no direct reset shortcut.

ValueMeaning
Quoted key equalitySelect the root queue baseline when that exact registered shortcut is pressed.
OmittedKeep the root as the baseline without assigning it a direct manual selector.

Effect and verification: Selecting the root replaces the active queue overlay with its complete baseline; it does not retain keys from the previous overlay. It is a selection rule, not a per-frame condition.

[queue] queue_size

Purpose: caps VP's converted-frame queue in whole frames. Syntax: integer >= 1. Omitted: VP uses its normal capacity policy.

ValueMeaning
1Minimum buffering; lowest queue latency but little resilience to a late renderer.
2 or higherMore scheduling headroom at the cost of potential buffered latency.

Effect and verification: Choose a capacity from measured latency and recovery needs; reserve 1 for a deliberately low-latency policy. Queue diagnostics reveal saturation and recovery.

[queue] lead_frames

Purpose: adds DirectShow presentation/timestamp lead in frames. Syntax: integer 0 through 16. Omitted: the standard timing lead is used.

ValueMeaning
0No configured extra lead; sensitive to downstream timing.
1 to 16Reserve the stated lead. Higher values can improve timing headroom while adding latency.

Effect and verification: This is VP/DirectShow timing, not a renderer-private queue setting. Change it with target_frames deliberately and inspect presentation diagnostics.

[queue] target_frames

Purpose: specifies the steady converted-frame target VP tries to maintain. Syntax: integer 0 through 16. Omitted: normal target policy.

ValueMeaning
0No requested steady reserve; suitable only when the rest of the pipeline is known stable.
1 to 16Keep that many frames of converted reserve when practical; higher values trade latency for resilience.

Effect and verification: A target cannot exceed physical opportunity created by the input and renderer. Use queue telemetry rather than assuming it is always reached.

[queue] active_picture_lookahead_frames

Purpose: enables diagnostic Alpha active-picture look-ahead depth. Syntax: integer 0 through 8. Omitted: 0.

ValueMeaning
0Disable the queued-future-frame diagnostic preview.
1 to 8Analyze up to that many existing queued future frames for diagnostic decisions.

Effect and verification: It logs decision evidence; it does not itself change crop or NLS pixels. Leave it at 0 for normal viewing unless diagnosing active-picture behavior.

[queue.<variant>] when

Purpose: selects a named queue overlay. Syntax: a source-state condition or ${key}=="<shortcut>" permitted by the conditional selection contract. Omitted: the section is not a matching override; the first named queue section can instead serve as the baseline when no root exists.

ValueMeaning
Manual key conditionSelect this overlay when its unique, quoted keyboard shortcut is pressed.
Source-state conditionSelect this overlay when the declared source values match; VP then inherits every queue key the overlay omits.

Effect and verification: A child may contain only supported queue keys. The selected overlay replaces the group state coherently; verify the selected queue profile in diagnostics.

[directshow] video_conversion

Purpose: selects VP's source-format conversion route. Syntax: a conversion token supported by the connected DirectShow input. Omitted: VP selects its normal ingress conversion path.

ValueMeaning
V210_TO_P010Use the supported v210-to-P010 conversion path.
Another input-supported tokenRequests that conversion only when the active source format supports it.

Effect and verification: This is an ingress choice, not an Alpha scaler or output format choice. Confirm negotiated input format and formatter diagnostics in the log.

[directshow] renderer_start_stop_time_method

Purpose: selects the DirectShow start/stop timestamp policy delivered to the renderer. Syntax: a method token supported by the active DirectShow renderer path. Omitted: normal timestamp policy.

ValueMeaning
RATIONAL_RATIONALUse VP's rational timestamp method for both start and stop timestamps.
Another renderer-supported tokenRequests that explicitly supported timing policy.

Effect and verification: A timing-method change can affect cadence and handoff stability. Verify it through timestamp and renderer diagnostics, not a single subjective observation.

[directshow] frame_offset

Purpose: applies a non-negative frame-offset policy to DirectShow timing. Syntax: AUTO or a non-negative integer. Omitted: normal automatic policy.

ValueMeaning
AUTOUse VP's automatic frame-offset resolution.
0 or higherRequest that fixed offset; use only with measured timing evidence.

AUTO behavior: VP keeps the automatic resolver rather than pinning a fixed offset. Effect and verification: a fixed number is not a picture delay control; consult cadence logs before overriding AUTO.

[directshow] renderer_nominal_range

Purpose: describes the nominal input range presented to the DirectShow renderer. Syntax: a supported range policy token. Omitted: normal input-range resolution.

ValueMeaning
AUTOUse the normal input-range inference/policy.
Renderer-supported range tokenRequest the corresponding nominal input interpretation.

AUTO behavior: range is resolved from the active input/render path, not from Alpha's output_range. Effect and verification: check source-format diagnostics before treating an output-range issue as an ingress issue.

[directshow.conversion] conversion_method

Purpose: selects the implementation family used by DirectShow conversion. Syntax: one of the listed tokens. Omitted: AUTO.

ValueMeaning
AUTOChoose the normal compatible conversion implementation.
SIMDPrefer the SIMD conversion path.
OPTIMIZEDPrefer VP's optimized conversion path.
STANDARDPrefer the standard conversion path.

AUTO behavior: VP chooses its normal compatible method; it does not force a specific CPU implementation. Effect and verification: use an explicit method only for measured compatibility or performance work.

[directshow.conversion] min_core_count

Purpose: sets the minimum conversion-worker policy. Syntax: positive integer. Omitted: normal worker policy.

ValueMeaning
1Permit a single conversion worker.
2 or higherRequire at least that many workers when the conversion path can use them.

Effect and verification: More workers can consume CPU without improving a GPU- or renderer-bound pipeline. Keep it no greater than max_core_count.

[directshow.conversion] max_core_count

Purpose: caps the conversion-worker policy. Syntax: positive integer. Omitted: normal worker policy.

ValueMeaning
1Limit conversion to one worker.
2 or higherAllow up to that many workers.

Effect and verification: Treat this as a CPU budget boundary, not a quality knob. Profile actual conversion load before raising it.

[directshow.ppm] ppm

Purpose: applies one source-timing correction in parts per million across cadences. Syntax: AUTO or an integer from -1,000,000 through 1,000,000. Omitted: automatic correction.

ValueMeaning
AUTOUse the automatic calibration sentinel.
Negative integerApply a measured negative source-rate correction.
0Apply no fixed correction.
Positive integerApply a measured positive source-rate correction.

AUTO behavior: VP retains automatic timing calibration instead of a fixed PPM value. Effect and verification: use a fixed correction only from repeatable timing evidence.

[shortcuts] render.<index>

Purpose: binds a shortcut to the one-based renderer selector index. Syntax: use render.<index>: <shortcut>, where index is positive and shortcut is a valid accelerator spelling. Omitted: no direct renderer shortcut.

ValueMeaning
Positive renderer indexSelect the matching one-based position in the local renderer list.
Valid keyboard shortcutUse that shortcut to select the associated renderer index.

Effect and verification: Indices refer to the actual renderer UI order. This is an index-based binding, so confirm the local renderer list after renderer installation or removal.

VideoProcessor Renderer (Alpha)

These settings affect only VideoProcessor Renderer (Alpha). Alpha feeds the bundled libplacebo renderer, but this page names only the values VP accepts. A root [vprenderer] is a baseline. If there is no root, the first named [vprenderer.name] section is the baseline and later names inherit it.

[vprenderer] when

Purpose: optionally provides a direct selector for the root Alpha display baseline. Syntax: ${key}=="<shortcut>" only; see the conditional selection contract. Omitted: the root remains the ordinary baseline without a direct reset shortcut.

ValueMeaning
Quoted key equalitySelect the root Alpha display baseline when that exact registered shortcut is pressed.
OmittedKeep the root as the ordinary baseline without assigning it a manual selector.

Effect and verification: This changes display-profile selection only. It does not edit the file, alter another group, or persist after VP exits.

[vprenderer] quality

Purpose: chooses Alpha's libplacebo render-parameter preset. Syntax: fast, balanced, or high. Omitted: high.

How this interacts with AUTO: Alpha copies the selected preset first, then applies the other [vprenderer] settings. For the renderer controls described below, AUTO means “retain that preset's value”; it is not a per-frame algorithm search. A non-AUTO setting overrides only its own part of the preset. The selections below are for Alpha's bundled libplacebo 7.360.1 build.

fast — lower rendering cost

Alpha selects pl_render_fast_params. It leaves advanced up/downscalers, sigmoidization, peak detection, dithering, and debanding disabled. If resizing is needed, libplacebo uses inexpensive built-in sampling (bilinear or nearest-neighbour according to the GPU path). Choose it to recover GPU headroom, not as a quality-equivalent alternative.

balanced — general-purpose quality

Alpha selects pl_render_default_params: Lanczos upscaling, Hermite downscaling, oversample frame mixing, default sigmoidization, default peak detection, and default dithering. Debanding remains disabled. Use it when high is more expensive than the GPU budget allows.

high — maximum bundled quality

Alpha selects pl_render_high_quality_params: EWA LanczosSharp upscaling, Hermite downscaling, oversample frame mixing, default sigmoidization, high-quality peak detection, high-quality color mapping, default dithering, and default debanding. It can cost substantially more GPU time and is intended for a capable discrete GPU.

Exact resolution of related AUTO controls

tone_mapping — every preset retains spline (pl_tone_map_spline), the bundled color-map default. gamut_mapping — every preset retains perceptual (pl_gamut_map_perceptual), also the bundled default.

peak_detection — fast disables it. balanced uses default analysis: 20-frame smoothing, scene thresholds 1 and 3, and a 100th-percentile peak. high uses the high-quality form of that analysis, changing the peak percentile to 99.995 so a tiny number of outlier pixels does not drive the result.

contrast_recovery — fast and balanced retain 0.0 (no recovery); high retains the libplacebo high-quality default of 0.30.

upscaler — fast uses no advanced scaler; balanced uses Lanczos (pl_filter_lanczos); high uses EWA LanczosSharp (pl_filter_ewa_lanczossharp). downscaler — fast uses no advanced scaler; balanced and high use Hermite (pl_filter_hermite).

deband — fast and balanced keep it disabled; high enables the libplacebo defaults: 1 iteration, threshold 3, radius 16, and grain 4. dithering — fast keeps it disabled; balanced and high enable default blue-noise dithering with a 6-entry LUT and temporal dithering off.

Practical consequence: selecting quality: high while leaving these controls at AUTO uses the high choices described above. Explicitly setting tone_mapping: spline or gamut_mapping: perceptual produces the same current selection as their AUTO values.

Limits and verification: a scaler choice matters only when the image is actually resized. libplacebo can disable an advanced feature the active GPU cannot support, regardless of the requested preset. Check Alpha's settings/render diagnostics and GPU render time after changing quality; the documented preset is the requested configuration, not a guarantee that unsupported hardware can execute every pass.

[vprenderer] tone_mapping

Purpose: selects HDR-to-target luminance mapping before output encoding. Syntax: one listed token. Omitted: AUTO.

ValueMeaning and trade-off
AUTOSelect spline, the bundled libplacebo color-map default.
splineSmooth highlight roll-off with a natural overall contrast balance; a good conservative HDR-to-SDR starting point.
bt2390BT.2390-style highlight roll-off; useful when a standards-oriented, gentler knee is preferred.
st2094-40Use ST.2094-40-oriented dynamic metadata behavior when compatible metadata is present; content-dependent results can vary.
reinhardSimple photographic compression; can retain highlight structure but may look flatter than spline on some material.

AUTO behavior: Alpha selects spline (pl_tone_map_spline) in every quality preset. Effect and verification: tone mapping changes highlight/contrast behavior and can make dynamic peak analysis relevant; Alpha's settings log reports the resolved mapping.

[vprenderer] gamut_mapping

Purpose: controls how colors outside the target gamut are brought into it. Syntax: one listed token. Omitted: AUTO.

ValueMeaning and trade-off
AUTOSelect perceptual, the bundled libplacebo gamut default.

[vprenderer] peak_detection

Purpose: controls dynamic peak analysis used by the color-mapping path. Syntax: one listed token. Omitted: AUTO.

ValueMeaning and trade-off

high_qualityExplicitly enable high-quality peak-detection parameters; more analysis work and potentially steadier/detailed adaptation.

[vprenderer] contrast_recovery

Purpose: restores local contrast after tone mapping. Syntax: AUTO or a number 0.0 through 1.0. Omitted: AUTO.

ValueMeaning and trade-off
AUTOUse 0.0 with fast or balanced, or 0.30 with high.

[vprenderer] upscaler

Purpose: chooses the filter used when Alpha enlarges video. Syntax: one listed token. Omitted: AUTO.

ValueMeaning and trade-off
AUTOUse the selected quality preset: built-in sampling for fast, lanczos for balanced, or ewa_lanczossharp for high.
ewa_lanczossharpSharp EWA Lanczos variant; high detail, higher GPU cost, and more ringing risk.
ewa_lanczosEWA Lanczos; detailed, generally less aggressive than the sharp variant.

bilinearLowest-cost soft interpolation; useful as a performance baseline.

Effect and verification: the setting matters only while enlarging; use native-resolution content to confirm a perceived change is not from a different stage.

[vprenderer] downscaler

Purpose: chooses the filter used when Alpha reduces video. Syntax: one listed token. Omitted: AUTO.

ValueMeaning and trade-off
AUTOUse the selected quality preset: built-in sampling for fast, or Hermite for balanced and high.
ewa_lanczosHigh-quality EWA Lanczos reduction; preserves detail at higher GPU cost.
bicubicModerate-quality reduction and cost.
bilinearLowest-cost reduction, softer fine detail.

AUTO behavior: fast has no advanced downscaler and falls back to built-in sampling; balanced and high select Hermite (pl_filter_hermite). Effect and verification: it matters only below native size; distinguish it from viewport cropping or projector scaling.

[vprenderer] deband

Purpose: controls the libplacebo debanding pass. Syntax: AUTO, on, or off. Omitted: AUTO.

ValueMeaning and trade-off
AUTOUse off with fast or balanced, or on with high.
onUse libplacebo's default deband parameters: 1 iteration, threshold 3, radius 16, and grain 4; can reduce smooth-gradient bands at GPU cost and with a small texture/noise trade-off.
offDisable the explicit deband pass; preserves source texture but leaves source banding visible.

AUTO behavior: fast/balanced resolve to off; high resolves to on with the parameters listed above. Effect and verification: examine slow gradients and dark skies; do not confuse this renderer pass with a configured custom debanding shader.

[vprenderer] dithering

Purpose: controls output dithering near final quantization. Syntax: AUTO, on, or off. Omitted: AUTO.

ValueMeaning and trade-off
AUTOUse off with fast, or on with balanced or high.
onUse default blue-noise dithering (6-entry LUT, temporal dithering off); it can hide quantization bands by adding controlled noise.
offDisable explicit dithering; may reveal gradients on low-bit-depth output.

AUTO behavior: fast resolves to off; balanced/high resolve to on with default blue-noise dithering. Effect and verification: a compatible LUT path can disable incompatible error-diffusion behavior; check the display diagnostics if a LUT is active.

[vprenderer] sdr_target_nits

Purpose: sets the target SDR white luminance used by Alpha color mapping. Syntax: number 40 through 500 nits. Omitted: 203 nits, libplacebo's standard SDR white.

ValueMeaning
100Conventional calibrated SDR starting point.
40 to 99Dimmer target for a deliberately lower-white calibration.
101 to 500Brighter target; match it to measured display calibration rather than room preference alone.

Effect and verification: It changes tone-mapping target assumptions. Align it with the LUT/reference target if a calibrated LUT is used.

[vprenderer] sdr_black_nits

Purpose: sets the target SDR black luminance. Syntax: AUTO or a number >= 0 and below sdr_target_nits. Omitted: AUTO.

ValueMeaning
AUTOSelect sdr_target_nits / 1000: for example, 100 nits selects 0.1 nit and the omitted 203-nit target selects 0.203 nit.
0Use a zero-nit target black when that matches the calibrated display path.
Positive number below target whiteUse a measured non-zero black level.

AUTO behavior: Alpha divides the selected SDR white by libplacebo's fixed SDR contrast constant of 1000. Effect and verification: this is calibration-sensitive; do not use it to compensate for an incorrect output range.

[vprenderer] output_presentation

Purpose: chooses Alpha's output-presentation policy. Syntax: AUTO, composed, or direct. Omitted: AUTO.

Shader groups

Shader groups are independent from Alpha color profiles. A root [shader.group] is an explicit off/baseline selection. A child is one shader member. For a single group, one matching member is selected; for type: multi, all matching children compose in stage/order sequence.

A shader is a GPU program inserted at a configured stage. A custom member uses the selected backend file as-is; an nls member uses VP's bundled nonlinear-stretch shader and its additional NLS contract, documented separately below. Both are selected, ordered, and disabled through the same shader-group configuration model.

Purpose: chooses whether a group's matching children are exclusive or composited. Syntax: single or multi. Omitted: single.

ValueMeaning

Effect and verification: Use multi only when the effects are intended to stack. A root with no child is the explicit off state.

Nonlinear Stretch (NLS) shader

NLS is VP's bundled nonlinear-stretch shader, not a separate renderer feature. It is still an ordinary shader_type: nls member: a shader group selects it, a root selection can turn it off, and its settings control its behavior. What makes it special is that VP supplies the shader with a runtime active-picture and viewport contract rather than leaving it to guess from a fixed source resolution.

StepHow NLS works
1. SelectA normal shader-group rule selects the standard or protected NLS member, or its root/off state. The when rule selects a mode; it does not identify every input aspect that should stretch.
2. MeasureVP waits for trusted, stable active-picture bounds from the current renderer generation. Until then it leaves mapping in a waiting/safe state.
3. ResolveVP compares the measured active-picture aspect with the selected viewport target. A near match passes through; a manageable mismatch uses horizontal or vertical nonlinear mapping; a ratio above the 1.5x safety limit uses safe fit instead.
4. RunThe bundled HLSL or GLSL shader receives the chosen axis, stretch ratio, active rectangle, and safe-fit inputs, then performs only that selected mapping. It does not choose the target aspect itself.
Viewport-driven behavior. A 4:3 active picture can map toward a 16:9 viewport. Scope content can pass through on a scope viewport. A 4:3 picture on a 2.35:1 viewport exceeds the safe stretch limit and remains a safe fit instead of receiving a destructive warp. The selected viewport, not a hard-coded input resolution, supplies the target.

Effect and verification: Treat geometry and center_protection as a pair. Use the shipped names unless the installed NLS shader explicitly supports another mode.

Event actions

An action launches one external command after an accepted event and when condition. Events describe a committed transition; values such as PQ, HDR, SDR, REC709, or a named viewport belong in when, not in an invented event name. For example, use on: source.eotf.changed with when: ${eotf}=="PQ".

Stable state boundary. Source/profile events are emitted only after VP has resolved one new immutable source/profile snapshot. They do not run per video frame. A source change can produce detailed source events, a profile event, and one state.committed event; configure one action for the level of granularity you need, rather than listing all of them on the same action.
Renderer boundary. VP evaluates renderer when it accepts the event. Source, profile, state, and renderer.ready events can be routed to the active built-in renderer, a declared renderer alias, or *. The refresh.* events are currently emitted only by Alpha's refresh controller, so target those with vprenderer or *.

[actions.<name>] renderer

Purpose: limits an action to the active output renderer. Syntax: vprenderer, a name declared in [renderer_alias], or *. Omitted: vprenderer.

ValueMeaning
vprendererRun only when the built-in Alpha backend is active. VP recognizes this backend directly; no alias or renderer-list position is required.
Declared renderer aliasRun only when the active renderer is at the one-based selector position assigned to that name in [renderer_alias].
*Run with any active renderer that publishes the selected event.

Effect and verification: Choose the narrowest renderer target that matches the external command. A named alias is local to its renderer order; verify its render.N log entry after installing, removing, or reordering renderers.

[actions.<name>] on

Purpose: lists the committed events that can trigger an action. Syntax: comma-separated supported event tokens. Omitted: required for an actionable section.

ValueMeaning
state.committedOne completed source/profile snapshot changed. Use this for a combined rule such as PQ plus a named viewport.
profile.changedOne or more effective profile selections changed.
profile.input.changed, profile.scaling.changed, profile.display.changed, profile.viewport.changed, profile.queue.changedThe named effective profile group changed. The root section resolves as base; a named section resolves as its configured name.
source.eotf.changed, source.transfer.changedThe stable source EOTF/transfer changed. Test the resulting value with ${eotf} or ${transfer}, for example PQ, HDR, or SDR.
source.colorspace.changed, source.primaries.changedThe reported source colorspace/primaries changed. Test ${primaries}=="REC709" or another documented source token.
source.format.changed, source.resolution.changed, source.width.changed, source.height.changedThe stable input format or dimensions changed.
source.scan.changed, source.interlaced.changed, source.hdr_metadata.changed, source.source_rate.changed, source.cadence.changedThe matching scan, interlace, HDR-metadata, nominal-rate, or cadence fact changed.
renderer.readyThe active selected renderer reached Ready. It is emitted again after a renderer rebuild; use it only for commands that are safe to repeat.
refresh.appliedRun after the requested refresh has been applied.
refresh.confirmedRun after VP confirms the refresh transition.
refresh.restoredRun after restoration of the previous refresh state.

Effect and verification: on names a transition, not a value. source.eotf.pq and vprenderer.viewport="scope" are rejected; use the event plus when instead.

[actions.<name>] when

Purpose: narrows an action to the state at its event boundary. Syntax: a supported expression for every event named by on; see the conditional selection grammar. Omitted: invalid for an actionable section; every action must declare a condition.

ValueMeaning
Refresh comparisonFor a refresh event, compare ${actual_refresh}, ${requested_refresh}, or ${previous_refresh}.
Current source/profile comparisonFor a source, profile, state, or renderer event, compare the documented source values and ${profile.input}, ${profile.scaling}, ${profile.display}, ${profile.viewport}, or ${profile.queue}.
Exit comparisonUse ${previous.<source-variable>} or ${previous_profile.<group>} to test the state being left. A root viewport is ${profile.viewport}=="base", never an empty string.
Event identity${event} is the selected event token. ${event_reason} is manual, source, renderer_ready, or refresh.

Effect and verification: The event selects the evaluation boundary; it does not limit the condition to the field that changed. For example, on: source.eotf.changed may test ${primaries}, ${profile.viewport}, and ${previous.eotf} together. The condition is evaluated against one immutable transition snapshot. Do not mix refresh-only variables with source/profile/renderer events in the same action: validation rejects a variable that is unavailable to any listed event.

[actions.<name>] run

Purpose: supplies the program and arguments run by an accepted event action. Syntax: an .exe, .bat, or .cmd path followed by optional arguments; a relative path is resolved beside VideoProcessor.cfg. Arguments may contain ${variable} placeholders. Omitted: no runnable action.

ValueMeaning
Executable/batch path plus argumentsRun that command only after the configured event and condition pass.
${eotf}, ${primaries}, ${profile.viewport}, ${previous.eotf}, ${event}Pass current, prior, profile, or event-bound values to the program. A placeholder may use any variable supported by every event named in on.
OmittedNo external command is associated with the action section.

Effect and verification: VP expands placeholders from the same immutable event snapshot before scheduling the delayed launch. Expansion applies to arguments, not the executable path. Text is substituted as-is; quote a placeholder in the command when the receiving program needs one argument, and every ${...} is treated as a variable reference (there is no literal escape form). A malformed, unsupported, or unavailable variable prevents the action from launching and is logged. Keep actions idempotent and short-lived. A path that does not end in a supported executable/batch extension is rejected by the configuration reader. When a condition matches, the action log records its event, scheduling, cancellation, expansion, or launch decision.

Examples

[actions.test_refresh]
renderer: vprenderer
on: refresh.confirmed
when: ${actual_refresh}==60
run: C:\Windows\System32\cmd.exe /c exit 0

Pass one committed PQ state to a named renderer's batch file

This uses a local renderer alias when an external controller should react only while that installed renderer is selected. The event is an EOTF change, but the condition and batch arguments also use primaries, the selected viewport, and the previous EOTF from the same committed state.

[renderer_alias]
cinema: 2

[actions.test_pq_cinema]
renderer: cinema
on: source.eotf.changed
when: ${primaries}=="REC709" && ${eotf}=="PQ"
run: C:\Scripts\source-state.cmd "${eotf}" "${primaries}" "${profile.viewport}" "${previous.eotf}"

Enter and leave a named scope viewport

The first action runs when the effective viewport becomes scope. The second sees the prior selection and returns external state when VP resolves the root base viewport.

[actions.test_scope_enter]
renderer: vprenderer
on: profile.viewport.changed
when: ${profile.viewport}=="scope"
run: C:\Windows\System32\cmd.exe /c exit 0

[actions.test_scope_leave]
renderer: vprenderer
on: profile.viewport.changed
when: ${previous_profile.viewport}=="scope" && ${profile.viewport}=="base"
run: C:\Windows\System32\cmd.exe /c exit 0

Practical starting points

Conservative SDR input to SDR output

[vprenderer]
sdr_target_nits: 100
quality: high
tone_mapping: AUTO
gamut_mapping: AUTO
sdr_target_primaries: REC709
output_range: AUTO
output_gamma: AUTO

Leave input transfer, scalers, deband, and dithering on AUTO until an observed source/output issue requires an override. This is a baseline fragment, not a profile or hotkey assignment.

HDR input to a calibrated SDR/projector target

[vprenderer]
sdr_target_nits: 100
sdr_black_nits: AUTO
tone_mapping: spline
gamut_mapping: perceptual
peak_detection: AUTO
contrast_recovery: AUTO
sdr_target_primaries: REC709
output_gamma: bt1886

Use the target luminance, black, transfer, and primaries measured for the projector/LUT. The example is a starting point, not a calibration prescription.

SDR BT.2020 display target

[vprenderer]
sdr_target_primaries: BT2020
report_bt2020_to_display: true
output_range: AUTO
output_gamma: AUTO

Enable this only for a display chain that is intentionally calibrated and signaled for SDR BT.2020. If it belongs in a named variant, add an appropriate generic when condition using the shared contract rather than copying a document-specific hotkey.

Scaling a lower-resolution source

[vprenderer]
quality: high
upscaler: ewa_lanczos
downscaler: AUTO
deband: AUTO
dithering: AUTO

Compare the chosen upscaler only while the source is enlarged. For native-size content, leave it at AUTO; a visible difference is likely coming from another stage.

NLS versus renderer scaling

Alpha's upscaler and downscaler resample pixels. An NLS shader changes presentation geometry before/after resizing according to its configured stage. Use the empty shader root to turn NLS off for an honest scaler comparison.

Independent queue, display, and viewport variants

Each group has its own root values and may have its own named variants. A matching queue rule changes queue policy only; a matching display rule changes Alpha display settings only; a matching viewport rule changes geometry only. Their resolved values compose without one group overwriting another. Define each group's when rule from the shared selection contract and choose conditions that represent the local source or workflow requirement.
