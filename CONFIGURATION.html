VideoProcessor configuration guide and reference

This page explains what each supported setting changes, when to choose each option, what happens when it is omitted, and where to look when the result is not what you expected. It covers the public configuration surface only.

Start here

VideoProcessor.cfg is optional. VP searches beside VideoProcessor.exe, then up to two parent directories, and finally the process working directory. The debug log identifies the file that was loaded. Use /config "C:\path\VideoProcessor.cfg" to select one explicit file for a process; a relative path starts at the working directory.

Renderer ownership matters. Shared VP sections configure capture, timing, shaders, viewport state, and profile selection. [vpvr.display] and [vpvr.general] configure only VideoProcessor Renderer (Alpha). They do not configure madVR.

Minimal madVR capture

[command_line]
capture_device: Decklink Quad HDMI Recorder (1)
renderer: DirectShow - madVR
queue_size: 32

Minimal built-in-renderer capture

[command_line]
capture_device: Decklink Quad HDMI Recorder (1)
renderer: VideoProcessor Renderer (Alpha)
queue_size: 32

[vpvr.display]
quality: high
sdr_target_nits: 100
sdr_target_primaries: REC709

[vpvr.general]
switch_refresh_rate: true

Start with the minimal example, verify capture and display, then add one concern at a time. Explicit output range, gamma, BT.2020 signalling, custom shaders, and timing corrections are calibration choices—not generic quality upgrades.

File syntax, comments, and precedence

  • Use INI sections such as [command_line] and assignments such as queue_size: 32. Names and enum values are case-insensitive.
  • Blank lines and lines beginning with # are ignored. Keep comments on their own line when clarity matters.
  • Booleans accept true/false, yes/no, on/off, and 1/0.
  • Paths containing spaces do not need quotes in the configuration file. A relative display-LUT path is resolved from the configuration directory; shader filenames are resolved only under the deployed shaders directory.
  • Duplicate keys are rejected by strict unified configuration. Unknown sections, unknown keys, malformed expressions, and profile settings in the wrong group also stop configuration validation.
  • Command-line arguments are applied after [command_line] and therefore win for the same startup option.

Precedence model

  1. VP begins with its runtime or UI default.
  2. A base value in [vpvr.display] replaces that renderer default.
  3. For each declared profile group, a persisted manual choice is restored when enabled; otherwise automatic rules are evaluated.
  4. A manual profile hotkey replaces the automatic selection for that group. A group reset hotkey returns only that group to automatic selection.
  5. Fields omitted by the selected profile inherit the base [vpvr.display] value. They do not acquire a second profile-specific default.
  6. Source metadata supplies evidence to automatic rules and field-specific AUTO decisions. AUTO is resolved independently for each field.

Application, capture, conversion, queue, and shader configuration is read at startup. Built-in-renderer base settings are read when the renderer is constructed. A non-viewport profile change rebuilds the built-in renderer transactionally; viewport-only changes normally apply live. A failed rebuild leaves the last successful renderer and persisted selection in place.

Capture and application settings

All fields in this section are optional keys under [command_line]. Omission keeps the corresponding application or saved UI default. Values are read at startup; changing the file while VP runs has no effect until the next process start.

capture_device

Selects the capture device by its displayed name. Use this for an unattended or device-specific configuration; omit it to keep VP's normal selection.

Type: text. Failure: an unavailable name cannot open capture; confirm the enumerated device names in the UI and log.

[command_line]
capture_device: Decklink Quad HDMI Recorder (1)

renderer

Selects a renderer by its displayed name. Use DirectShow - madVR for madVR or VideoProcessor Renderer (Alpha) for the built-in renderer. An empty or omitted value keeps the current/default selection.

Type: text. Failure: a renderer whose required runtime is unavailable is not selectable; startup logs the registered renderer order.

fullscreen

Starts video fullscreen when true. Default when omitted is the normal window state. This chooses initial presentation only; it does not select exclusive versus windowed fullscreen.

windowedfullscreenmode

When true, fullscreen uses a borderless window. When false, VP may use the renderer's exclusive path. Borderless mode usually switches applications more smoothly; exclusive mode may be useful when a renderer or display chain depends on it.

queue_size

Sets the maximum DirectShow renderer-frame queue. A larger queue gives more protection from short processing stalls but consumes more memory and adds recovery time; it is not a picture-quality control.

Type: integer ≥ 1. Default: VP's normal queue setting. Failure: zero or non-numeric input fails startup validation.

alpha_queue_size built-in renderer

Overrides queue depth only for the built-in renderer. Omit it to use queue_size. Use it when the two renderers need different latency/stability tradeoffs.

Type: integer ≥ 1. Invalid input is logged and the normal queue setting is retained.

scene_detect

For P010 output, locks output timestamps to measured display cadence and prefers a required whole-frame repeat or drop at a detected scene cut. If no cut arrives before a full-frame phase error, VP corrects at the hard limit to protect queue depth and audio/video alignment.

Type/default: Boolean, false when omitted. Scope: retained but inactive for non-P010 output.

disable_detection_features diagnostics

Forces scene analysis and subtitle repositioning/OCR off and disables the Scene Detect selector. Use this to isolate renderer and queue timing from optional detection work.

Type/default: Boolean, false when omitted.

scene_correction_basic DirectShow only

Chooses the renderer-repeat correction when true. False uses the normal upstream-sample correction. Keep false unless comparison logs show the renderer-specific basic method is required; the built-in renderer has one native correction path and ignores this choice.

subtitle_reposition DirectShow P010

  • false/off: do not reposition detected subtitles.
  • true/basic: use lower-cost Windows OCR-assisted placement; suitable when the advanced model is unavailable.
  • advanced: use the model-assisted tracker for steadier geometry at greater processing cost.

Omitted means off. The debug log reports detector state and accepted geometry.

[shaders.*] stable_geometry_deadband_percent NLS geometry

Default 2; allowed range 0–5. Retains an already trusted active-picture rectangle through a small measured boundary change. The allowance is capped across each full axis, so matching changes at two opposing edges cannot double it. This never promotes an untrusted crop. Keep the default unless measured content transitions make a larger value necessary.

newlldv

Enables VP's opt-in LLDV heuristic for stable BT.2020 + SDR input without static HDR metadata. Enable only when the source is known to send LLDV; genuine BT.2020 SDR can look identical to the capture device.

Type/default: Boolean, false. Requires both hdr_colorspace: FOLLOW_INPUT_LLDV and hdr_luminance: FOLLOW_INPUT_LLDV.

noui

Shows only the windowed video panel when true. Use for appliance-style operation; keep false while diagnosing because the normal controls remain accessible.

startminimized

Starts the main window minimized when true. This does not delay capture or change rendering behavior.

frame_offset

Sets the capture timing-clock frame offset in whole milliseconds for clock-based timestamp modes. It calibrates the DeckLink capture timestamp used by those legacy modes and diagnostics.

Rational-Rational: unavailable. VP displays N/A, applies an effective zero offset to the capture clock, and excludes this setting from its synthetic DirectShow presentation timeline and latency calculations. The configured value is preserved for a later switch back to a clock-based mode.

AUTO behavior: The current legacy tuner derives an offset from queue capacity and cadence and can update it while running. It is not an end-to-end latency measurement.

Values: AUTO or integer ≥ 0. Invalid values fail command-line validation.

video_conversion

V210_TO_P010 enables VP's supported-input-to-P010 conversion path. Choose it when the renderer/timing features require P010; omit it to keep the captured format. Conversion consumes CPU, so verify conversion percentage and dropped-frame statistics.

container_colorspace

Overrides the output container primaries tag; it does not by itself transform pixels. Choose the value that describes the pixels being sent:

  • BT2020: UHD wide-gamut container; REC709: normal HD SDR.
  • P3_D65, P3_DCI, P3_D60: P3 variants with their named white point.
  • REC601_525 and REC601_625: SD standards for 525- and 625-line sources.

Omit to follow VP's normal container choice. A wrong tag causes downstream colour interpretation errors.

hdr_colorspace

  • FOLLOW_INPUT: report captured input primaries; safest general choice.
  • FOLLOW_INPUT_LLDV: follow input while allowing the LLDV path when its prerequisites match.
  • FOLLOW_CONTAINER: use the container_colorspace choice.
  • BT2020, P3, REC709: force that HDR primaries report for a controlled workflow.

This controls HDR metadata presented downstream, not the built-in renderer's SDR target.

hdr_luminance

  • FOLLOW_INPUT: pass captured mastering/max-light information.
  • FOLLOW_INPUT_LLDV: follow input and permit synthetic LLDV luminance metadata.
  • HDR_LUMINANCE_USER: use the luminance values entered in the VP UI.

renderer_start_stop_time_method DirectShow only

Selects which clock supplies sample start and stop timestamps. Keep the UI/default method unless a timing investigation identifies a specific requirement.

  • CLOCK_SMART and CLOCK_SMART2: adaptive clock-derived methods; normal comparison candidates.
  • RATIONAL_RATIONAL: rational cadence for both timestamps; useful for deterministic fractional rates. CLOCK_RATIONAL uses clock start and rational stop.
  • CLOCK_THEO, CLOCK_CLOCK, THEO_THEO: diagnostic combinations of measured clock and theoretical cadence.
  • CLOCK_NONE, THEO_NONE, NONE: omit stop timing or both timestamps; specialized diagnostics, not quality modes.

renderer_nominal_range DirectShow input metadata

FULL declares 0–255 range, LIMITED declares video 16–235 range, and SMALL declares 48–208. This describes samples handed to DirectShow; it is separate from built-in-renderer output_range.

AUTO behavior: sends an unknown nominal-range declaration so the selected renderer infers the source. VP makes no further per-frame choice. Use the renderer's diagnostics to see its effective interpretation.

renderer_transfer_function DirectShow input metadata

Overrides how DirectShow describes the source transfer. Common choices are PQ for HDR10, HYBRID_LOG_GAMMA for HLG, REC709 for HD video, and BT2020/BT2020_CONST for BT.2020 transfer declarations. GAMMA_1.8, GAMMA_2.0, GAMMA_2.2, GAMMA_2.6, and GAMMA_2.8 are explicit power curves. LINEAR_RGB, 204M, 8BIT_GAMMA_2.2, LOG_100_1, and LOG_316_1 are specialized source declarations.

AUTO behavior: sends an unknown transfer declaration and lets the selected DirectShow renderer infer it from the remaining media information. The choice is made when the media type is negotiated, not by a global VP AUTO policy.

Forcing the wrong transfer changes brightness and contrast. It does not convert pixels into the named transfer.

renderer_transfer_matrix DirectShow input metadata

BT709 is normal HD YCbCr, BT601 is normal SD, and BT2020_10/BT2020_12 describe BT.2020 10-/12-bit matrix coefficients. 240M, FCC, and YCgCo are specialized source matrices.

AUTO behavior: sends an unknown matrix declaration for renderer inference at media-type negotiation. Incorrect forcing produces hue and saturation errors.

renderer_primaries DirectShow input metadata

BT709 is HD/Rec.709, BT2020 is UHD wide gamut, and DCI-P3 is cinema P3. NTSC_SYSM, NTSC_SYSBG, CIE1931_ZYX, and ACES are specialized mastering/source declarations.

AUTO behavior: sends unknown primaries so the DirectShow renderer decides from source/media metadata during negotiation.

Queue, logging, and timing settings

[queue] target_frames DirectShow

Keeps this many converted VP frames behind the DirectShow delivery worker after priming. It controls only the VP-owned queue; madVR's internal queue remains independently configured and is not queryable by VP.

Omitted behavior: defaults to 4 frames. An explicit 0 requests a literal zero-frame steady target.

Type/range: whole frames, 0–16, bounded by the active VP queue capacity. The former steady_reserve_frames name remains readable for compatibility but must not be combined with this key.

[queue] lead_frames DirectShow timing

Schedules each timestamped DirectShow sample this many source-frame intervals ahead of the graph clock. It is a presentation margin for renderer delivery, not a VP queue target and not a measurement or configuration of madVR's private queues.

Omitted behavior: defaults to 1 frame. An explicit 0 requests no additional scheduling margin.

Type/range: whole source frames, 0–16. One frame is approximately 41.7 ms at 23.976 Hz and 16.7 ms at 59.94 Hz. Changes apply when the renderer graph is built or rebuilt. The former [directshow] presentation_lead_frames name remains readable for compatibility but must not be combined with this key.

[logging] debug_log_retention

Total VP debug-log files retained, including active logs\vp_debug.log. At startup the prior active log becomes .0, existing numbered archives shift up, and the oldest is pruned.

Type/default: integer 1–100; default 10. Invalid, zero, duplicate, or out-of-range input safely resolves to 10. VP does not create the logs directory.

[queue_recovery] reset_after_render_restart_seconds

Seconds VP waits after startup/restart, a fullscreen/windowed presentation retarget, or a queue high-water event before flushing and re-priming the live queue. A fullscreen/windowed retarget first performs its immediate renderer-window transaction, then uses this delay for one LiveQueue-only normalization reset. Increase only when the renderer or HDMI path needs longer to settle.

Type/default: integer ≥ 1; default 5.

[queue_recovery] reset_queue_too_large_percent

Schedules queue recovery when either the raw or converted queue reaches this percentage of its own capacity. It is not a percentage of their combined OSD total. If either queue reaches its hard capacity, VP immediately escalates the same recovery instead of waiting for the configured delay.

Type/default: integer 1–100; default 75.

[display_refresh_rate_override] <nominal_hz>

Maps a nominal input rate to a known exact display rate. A truncated key is preferred—23 matches 23.976—then a key within 0.5 Hz is considered. An active exact override appears with * in the OSD and is named in the log.

AUTO behavior: explicitly keeps VP's normal display measurement for that nominal rate. VP measures the display, and the result may change after display/refresh transitions. The loader logs measurement enabled.

[display_refresh_rate_override]
23: 23.976024
59: AUTO

[ppm_correction] <nominal_hz>

Applies a parts-per-million timing correction to rational timing modes. Positive values make the video stream slightly faster; negative values make it slower. Keys use truncated cadence, such as 59 for 59.94.

AUTO behavior: VP begins at zero correction and calibrates from live queue/timing evidence for the matching cadence. If the section or a valid match is absent, automatic calibration is also used.

HDR, LLDV, and P010 conversion

DeckLink capture does not expose the HDMI Dolby Vision VSIF, so LLDV recognition is evidence-based. With newlldv: true and both LLDV follow modes selected, VP requires stable BT.2020 + SDR without static HDR metadata for 1.5 seconds before changing to PQ and supplying synthetic metadata.

[lldv] max_cll

Overrides synthetic maximum content light level in nits. Omission uses 1000 nits for either LLDV detection path. Use a measured/source value when known.

Range: finite number ≥ 0.

[lldv] max_fall

Overrides synthetic maximum frame-average light level in nits. Omission uses 1000 for direct detection and 401 for the BT.2020 + SDR heuristic.

Range: finite number ≥ 0.

[lldv] mastering_min_luminance

Overrides synthetic mastering-display black level in nits. Omission uses 0.0001 or 0.001 depending on the active LLDV evidence path.

Range: finite number ≥ 0.

[lldv] mastering_max_luminance

Overrides synthetic mastering-display peak in nits. Omission uses 1000 for direct detection and 4000 for the BT.2020 + SDR heuristic.

Range: finite number > 0.

[p010_conversion] ConversionMethod

  • SIMD: AVX2 path, threaded for sufficiently tall frames; normally fastest on supported CPUs.
  • OPTIMIZED: optimized scalar conversion; compatibility/performance fallback without AVX2.
  • STANDARD: simplest scalar implementation; best reserved for comparison and troubleshooting.

AUTO behavior: for non-720p conversion, VP checks AVX2 support and frame height. It selects threaded SIMD for frames at least 720 lines high, non-threaded SIMD for smaller frames with AVX2, and optimized scalar otherwise. The formatter is chosen per frame size/CPU evidence; 720p uses its dedicated conversion path.

[p010_conversion] MinCoreCount

Minimum worker count for threaded conversion. More workers do not improve image quality and may compete with capture or rendering. Use a whole number; 0 is raised to 1. The effective count cannot exceed the logical processors available to Windows, and conversion never uses more than eight workers. Values from 1 through 8 are the useful range.

Default: 1.

[p010_conversion] MaxCoreCount

Caps conversion workers. Use a non-negative whole number. 0 selects an automatic limit that normally leaves two logical processors for Windows and the user interface. A positive value is limited to the logical processors available, raised to MinCoreCount when necessary, and hard-capped at eight workers.

Default nuance: when the entire section is absent, smart defaults choose two workers on systems with at least eight physical cores and one worker on smaller systems. When the section exists but this field is omitted, the section-level fallback is two.

[command_line]
video_conversion: V210_TO_P010

[p010_conversion]
ConversionMethod: AUTO
MinCoreCount: 1
MaxCoreCount: 2

Shader configuration and viewport-aware NLS

VP installs renderer-native shaders without a CPU readback. madVR uses HLSL; the built-in renderer uses mpv-style GLSL hooks. Automatic effects are checked in rules order and the first compatible signal/rate match wins. A rule with shortcut is manual. Rules sharing one shortcut form a renderer-specific pair while keeping one selection state.

[shaders] enabled

Enables shader rule evaluation. Boolean; default false. When false or omitted, no configured shader is installed.

[shaders] rules

Comma-separated effect identifiers, evaluated left to right. Every name must have one matching [shaders.<name>] section. Put the most specific automatic rule first.

[shaders] default

The result when no automatic rule matches. The supported value is none, which leaves the shader chain empty.

[shaders] fallback_shader_model

madVR HLSL model used only when the shader file does not declare its minimum profile. ps_3_0 (default) is the most capable; ps_2_0, ps_2_a, and ps_2_b exist for older shader compatibility and may reject newer instructions.

[shaders.*] label

Friendly text in the OSD and log. Omission uses the rule identifier.

[shaders.*] type

Set nls for VP's typed nonlinear-stretch behavior; omit for a general shader. Typed NLS derives geometry from the selected viewport and validates the NLS fields below.

[shaders.*] signal

ANY (default) matches every signal, SDR only SDR, and HDR HDR gamma, PQ, HLG, or detected LLDV. Use this to avoid applying a shader in the wrong colour domain.

[shaders.*] frame_rates

ANY (default) or comma-separated nominal integers. VP uses its displayed truncated cadence: 23 matches 23.976, 29 matches 29.97, and 59 matches 59.94.

[shaders.*] none

When true, selecting the effect deliberately installs no shaders. Use for an explicit “off” selection. Default false.

[shaders.*] shortcut

Makes the effect manual. Uses the shortcut syntax below. Same-chord HLSL and GLSL effects form one selector; each renderer loads only its compatible file.

[shaders.*] file

Filename only: .hlsl for madVR or .glsl/.hook for the built-in renderer. VP resolves it under shaders beside the executable and rejects directory components. A missing or failed file disables that effect/stage and is logged.

[shaders.*] stage

pre_resize (default) runs before madVR scaling and is appropriate for geometry/denoise at source resolution. post_resize runs after scaling and is appropriate for final-size sharpening. Built-in typed NLS uses its resizable MAIN hook.

[shaders.*] output_aspect_ratio

For a general DirectShow shader, declares native, a decimal, or a ratio such as 2.35:1 for the output media contract. Typed NLS derives this from the selected viewport, so omit it there.

[shaders.*] param_<name>

Finite compile-time token value for a general custom shader. The suffix identifies the shader token. This is a low-level authoring control: wrong values can fail compilation or produce invalid output.

Typed nonlinear stretch (NLS)

geometry

classic uses the established power curve and allows more centre movement; protected preserves a central fraction more strongly and moves more distortion toward the edges. Choose protected for faces/subtitles near centre, classic for the smoothest full-width redistribution.

strength

0.0–1.0 scale of the derived correction. 0 is effectively linear; 1 applies the complete mapping. Reduce it when the full stretch is visually too strong.

center_protection

Protected fraction of picture width, 0.0–0.45, used by geometry: protected. Higher values preserve a wider centre but compress more strongly near the sides.

curve

0.5–4.0 distribution curve. Higher values delay distortion toward the sides; lower values spread it more evenly. This changes distortion placement, not the final target aspect.

quality

madVR NLS reconstruction: low, medium, high, or very high. Higher settings spend more GPU work reducing resampling artifacts. Start with high; lower for dropped frames, raise to very high only with measured headroom. Built-in NLS uses the renderer scaler instead.

tolerance_percent

0–50 percent. If active picture is already this close to the selected viewport, VP uses linear passthrough to avoid a small, distracting stretch. Five percent is a practical starting point.

[shaders]
enabled: true
rules: nls_madvr,nls_vpvr,nls_off
default: none

[shaders.nls_madvr]
label: Nonlinear Stretch
shortcut: N
type: nls
file: NLS.hlsl
stage: pre_resize
geometry: protected
strength: 1.0
center_protection: 0.35
curve: 2.0
quality: high
tolerance_percent: 5

[shaders.nls_vpvr]
label: Nonlinear Stretch
shortcut: N
type: nls
file: NLS.glsl
geometry: protected
strength: 1.0
center_protection: 0.35
curve: 2.0
tolerance_percent: 5

[shaders.nls_off]
label: NLS Off
shortcut: n
none: true

Shared profile groups, selection, and viewport

Profiles are independent groups: input, scaling, display, and viewport. Declare a group in [profile_groups.<group>], then define its members in [profiles.<group>.<name>]. Input/scaling/display settings affect only the built-in renderer; viewport state is shared with DirectShow shaders and the built-in renderer.

[general] persist_profile_selection

Global Boolean default for saving successful manual profile selections to VideoProcessor.state. Default true. Per-group configuration may override it.

[general] event_action_delay_seconds

Default delay before completed-event programs run. Whole seconds 0–30; default 0. An action's own delay wins.

[profile_groups.*] profiles

Required comma-separated member identifiers in tie-break order. Each member needs a matching profile section; names auto, none, and default are reserved.

[profile_groups.*] default

A listed profile or AUTO. A named default is selected when no source rule matches.

AUTO behavior: when no profile rule matches, the group contributes no overrides and every field inherits its [vpvr.display] base value. VP re-evaluates on relevant source changes.

[profile_groups.*] when

Optional key-only expression that returns this group to automatic selection, for example $key=="F4". It does not reset other groups.

[profile_groups.*] persist_profile_selection

Boolean override of the global persistence setting for one group. Set false for source-driven input/scaling groups so a manual test cannot unexpectedly return after restart.

[profiles.*.*] when

Optional expression using == != < <= > >= && || ! and parentheses. Source variables include $transfer/$eotf, $primaries/$colorspace, $format, $hdr_metadata, $interlaced/$scan, $source_rate/$cadence, $width, $height, and $resolution. $key is the current physical shortcut chord.

[profiles.*.*] priority

Integer −100000 to 100000, default 0. Highest matching priority wins; then the condition with more comparisons; then declared profiles order. Use priority only where overlapping rules are intentional.

Viewport profile fields

screen_aspect

Physical viewport aspect, 1.0–4.0, as decimal or ratio (16:9, 2.35:1). Omission is 16:9. This drives shared NLS and subtitle placement; the profile name itself has no geometric meaning.

subtitle_fit

Boolean, default false. When true, VP may reposition detected subtitles into the selected viewport. This requires the applicable subtitle processing path.

subtitle_hold_seconds

0–30 seconds, default 2. Retains a confirmed subtitle position through short detector gaps; too high can hold stale placement.

subtitle_padding_pixels

Whole pixels 0–500, default 20. Adds clearance from the viewport edge after repositioning.

[profile_groups.viewport]
profiles: normal,scope
default: normal

[profiles.viewport.normal]
when: $key=="F3"
screen_aspect: 16:9

[profiles.viewport.scope]
when: $key=="F2"
screen_aspect: 2.35:1
subtitle_fit: true
subtitle_hold_seconds: 2
subtitle_padding_pixels: 30

Built-in renderer (vpvr)

[vpvr.display] supplies base values for VideoProcessor Renderer (Alpha). Input, scaling, and display profiles may override only their matching fields. Omitted fields use the defaults below; omitted profile fields inherit the base value. Invalid canonical values fail strict configuration before capture begins.

Input treatment

tone_mapping

Maps HDR brightness into the configured SDR target. It has no visible effect when tone mapping is unnecessary.

  • spline: smooth, balanced highlight roll-off; the best general explicit choice.
  • bt2390: standards-oriented knee/roll-off; useful for predictable mastering-style behavior.
  • st2094-40: scene-aware curve designed around dynamic-metadata-style processing; useful for difficult highlight distributions even when metadata is estimated.
  • reinhard: simple global compression; robust and inexpensive, but can look flatter.

AUTO behavior: the built-in renderer keeps the tone-mapping function supplied by the selected libplacebo quality preset. Source mastering/peak evidence then drives that function. The effective settings and colour-map choice are logged; the choice can change after renderer rebuild/profile selection, not frame by frame as a different enum.

Default: AUTO. Lifecycle: renderer rebuild. Example: tone_mapping: spline.

gamut_mapping

Handles colours outside the target primaries.

  • perceptual: compresses the gamut while preserving visual relationships; best general choice.
  • softclip: gently clips near the boundary; preserves in-gamut colours but may lose extreme saturation.
  • relative: colorimetric boundary mapping; useful for measured workflows, but hard clipping may be visible.
  • desaturate: reduces saturation to bring colours in range; safe but may look muted.

AUTO behavior: uses the gamut function supplied by the current libplacebo quality preset. The renderer chooses, while target/source primaries provide the evidence. The log reports the active gamut function with display-LUT diagnostics.

Default: AUTO. Lifecycle: renderer rebuild.

peak_detection

Controls frame analysis used to estimate HDR peaks for tone mapping.

  • OFF: use metadata/nominal source information only; lowest GPU cost and most stable, but misses scene changes.
  • ON or HIGH_QUALITY: force high-quality peak analysis; best adaptation at greater GPU cost.
  • DEFAULT: same resolution as AUTO, retaining the quality preset's normal analysis.

AUTO behavior: keeps the peak-detection parameters in the selected quality preset. The renderer combines those parameters with current HDR frames and metadata. The settings log reports peak detection on/off; a profile/rebuild can change the preset.

Default: AUTO. Lifecycle: renderer rebuild.

contrast_recovery

Restores local contrast that tone mapping can flatten. Values 0.0–1.0; higher is stronger and can exaggerate halos/noise. Start near 0.2–0.3 only when the mapped image looks flat.

AUTO behavior: does not force a numeric override; libplacebo's selected quality preset supplies its normal contrast-recovery behavior. The renderer makes the decision during construction.

Default: AUTO. Lifecycle: renderer rebuild.

sdr_input_transfer

Overrides how captured SDR code values are decoded. BT1886 is typical reference-video viewing, SRGB typical desktop graphics, and 1.8, 2.0, 2.2, 2.4, 2.6, 2.8 are explicit power curves. This is independent of output gamma.

AUTO behavior: leaves the captured SDR transfer metadata unchanged. The renderer uses the coherent source snapshot; it does not guess from the output target. The effective input transfer is logged.

Use an override only for a known mis-tagged or comparison source; the wrong value changes midtone brightness.

Scaling and cleanup

There is no universally “best” scaler. Choose by the amount of resizing, visible ringing/softness, and measured GPU headroom. The quality preset also controls other renderer work, so compare with the stats overlay at the hardest cadence you use.

quality

  • fast: lowest GPU cost; use to recover headroom or diagnose overload, with softer/less refined processing.
  • balanced: libplacebo default preset; good for limited GPUs or high-rate UHD.
  • high: highest shipped preset and the VP default; best starting point when render time stays comfortably below the frame interval.

Default: high. Lifecycle: renderer rebuild. This sets a processing preset, not output bit depth or cadence.

upscaler

  • EWA_LANCZOSSHARP: sharpest detailed option; best for substantial enlargement with GPU headroom, but can reveal ringing/noise.
  • EWA_LANCZOS: high-detail reconstruction with slightly gentler sharpening; strong general-quality choice.
  • BICUBIC: smoother and cheaper; good compromise when Lanczos is too slow or too crisp.
  • BILINEAR: cheapest and softest; use for troubleshooting or very constrained GPUs.

AUTO behavior: leaves the upscaler selected by the active quality preset. Libplacebo decides at renderer construction; it does not benchmark the GPU. The settings log reports the effective filter name or built-in.

Default: AUTO. Fallback: an unavailable explicit filter prevents renderer setup rather than silently selecting a different named algorithm.

downscaler

  • EWA_LANCZOS: best fine-detail retention for reduction, with the highest cost and possible ringing.
  • BICUBIC: smoother, cheaper compromise that often looks calmer on noisy video.
  • BILINEAR: fastest but loses the most fine detail; diagnostic/low-headroom choice.

AUTO behavior: retains the downscaler from the selected quality preset. It is resolved during renderer construction and reported in the renderer settings log.

Default: AUTO. Lifecycle: renderer rebuild.

sigmoid

Applies sigmoid-domain scaling to reduce ringing around strong edges. ON can look cleaner with sharp scalers but changes their character; OFF is useful for exact filter comparison.

AUTO behavior: keeps the selected quality preset's sigmoid setting. Resolution occurs at renderer construction and is stable until rebuild.

deband

ON smooths false contour bands, useful on compressed gradients but capable of removing subtle texture. OFF preserves the source exactly and costs less.

AUTO behavior: uses the quality preset's debanding policy. The settings log reports effective on/off after renderer construction.

deband_strength scaling profiles

OFF disables debanding. LIGHT and DEFAULT currently both enable libplacebo's default debanding parameters; there is no present image-quality difference between those two tokens. Prefer DEFAULT so intent is clear.

This profile-only selector overrides the inherited deband state and requires a renderer rebuild.

dithering

ON adds controlled noise to hide quantization bands, normally desirable for the final 10-bit output. OFF is useful for measurement or diagnosing noise but may expose gradients.

AUTO behavior: retains the active quality preset's dither parameters. When a target 3D LUT is active, VP selects an ordered dither method to avoid a known GPU shader-register conflict; this fallback is logged.

SDR display target and output contract

sdr_target_nits

SDR reference white/peak used for tone mapping, 40–500 nits. Default when omitted is 203. Use the calibrated peak your display actually produces in the selected mode; 100 is common for a dark reference environment.

Lifecycle: renderer rebuild. Invalid values fail strict validation.

sdr_black_nits

Measured display black in nits. An explicit value must be ≥ 0 and below target white. Use 0 for an ideal-black target only when appropriate to the display/calibration.

AUTO behavior: VP calculates sdr_target_nits / 1000 using the renderer's SDR contrast constant. At 100-nit white this is 0.1 nit. The effective value is printed in the renderer settings log.

output_presentation

  • COMPOSED: stable Windows DWM/BitBlt path; best compatibility and desktop integration.
  • DIRECT: requests a flip-model, direct-eligible path; required for BT.2020 signalling and useful for low-latency/fullscreen chains, but Windows still decides actual promotion.

AUTO behavior: uses composed presentation for normal Full/Rec.709 output, but creates a flip candidate for Limited range or BT.2020. If AUTO Limited negotiation fails, VP recreates the stable composed Full/sRGB path and logs the fallback. Embedded preview always uses composed Full/sRGB Rec.709.

output_range

FULL emits full-range RGB and is the normal Windows desktop contract. LIMITED requests studio-range RGB for a display chain calibrated for it; a range mismatch produces raised/crushed blacks and whites.

AUTO behavior: requests the normal Full/sRGB swapchain contract. With explicit Limited and AUTO presentation, VP verifies DXGI support before use and falls back safely if unavailable. Requested and actual contracts are logged.

output_gamma

SRGB is the supported full-range desktop transfer. 2.4 is the supported limited-range reference transfer. BT1886, 1.8, 2.0, 2.2, 2.6, and 2.8 are accepted calibration requests, but VP rejects any range/gamma pair for which Windows has no matching safe DXGI declaration rather than mislabeling output.

AUTO behavior: resolves to sRGB/G22 for Full output and gamma 2.4 for Limited output. Resolution uses the requested range/primaries and verified DXGI capabilities during renderer construction. The negotiation log shows requested and actual gamma.

sdr_target_primaries

REC709 (default) is the safest SDR target and matches normal desktop/display expectations. BT2020 renders into a wide-gamut target and requires a flip-model path plus a display deliberately placed in the matching mode. BT.2020 is not inherently “better” if the display chain is not calibrated for it.

report_bt2020_to_display

When true with a BT.2020 target, requests NVIDIA output reporting for BT.2020. Default false: the display must be switched manually. It is ignored for Rec.709. If NVIDIA reporting is unsupported, VP disables the request, rebuilds the BT.2020 output safely, and logs that result.

Display 3D LUT

lut

Optional .cube display-transform filename/path, resolved relative to the configuration directory and constrained to remain under it. Empty disables the LUT. The LUT is applied at the target/native post-encode stage only when its declared reference contract matches actual output.

Missing, malformed, escaped, contract-mismatched, or render-failing LUTs are rejected and VP continues without the LUT. OSD/log status explains the reason.

lut_reference_primaries

REC709, P3_D65, or BT2020 declares the LUT's expected target primaries.

AUTO behavior: leaves primaries unspecified for contract validation, so this dimension does not reject the LUT. Use an explicit value for a calibrated LUT.

lut_reference_transfer

SRGB, BT1886, 2.2, or 2.4 declares the transfer for which the LUT was built.

AUTO behavior: leaves transfer unspecified in contract validation. It does not transform or inspect the LUT to discover a curve.

lut_reference_range

FULL or LIMITED declares the LUT's expected signal range.

AUTO behavior: leaves range unspecified for validation. Explicit is safer for a calibrated LUT because a mismatch disables it rather than applying it to the wrong code range.

lut_reference_nits

40–500 nit target for which the LUT was built.

AUTO behavior: stores zero as “unspecified,” so target luminance does not reject the LUT. It does not measure the LUT or display.

Renderer session policy

[vpvr.general] switch_refresh_rate

Boolean, default true. Lets the built-in renderer run its display refresh transaction for source cadence. False makes no refresh request and therefore no refresh-completed event. Read at renderer construction; changing it requires rebuild.

[vpvr.general] output_diagnostics

Boolean, default false. Enables additional output-contract/pixel diagnostics for troubleshooting. It adds work and log volume; do not treat it as a quality setting.

[vpvr.general] diagnostic_disable_shader_cache

Boolean, default false. Disables use of the persistent GPU shader cache for one renderer instance while leaving the file intact. Use only to diagnose stale/corrupt cache behavior; compilation will be slower.

Shortcuts and completed-event actions

Shortcut modifiers are Ctrl, Alt, and Shift. Keys are one letter/number, F1–F24, Escape, or Enter. A lowercase letter has no Shift; uppercase adds Shift. Invalid or duplicate fixed bindings retain the built-in binding when available.

[shortcuts] auto_set

Runs VP's automatic setup command. Built-in default Ctrl+Shift+A.

fullscreen_exit

Leaves fullscreen. Default Escape.

fullscreen_toggle

Toggles fullscreen. Default Alt+Enter.

toggle_stats_overlay

Shows/hides VP performance and renderer statistics. Default Ctrl+I; use it to compare scaler/quality GPU headroom.

pq_set

Runs VP's PQ metadata setup command. Default Ctrl+Shift+P.

renderer_restart

Performs a controlled renderer reconstruction. Default Shift+R.

renderer_reset

Resets/re-primes renderer delivery without changing the selected renderer. Default lowercase r.

capture_1 … capture_4

Select capture inputs 1–4. Defaults Ctrl+1 through Ctrl+4.

video_conversion_off, video_conversion_p010

Turns conversion off or selects P010. Defaults lowercase v and uppercase V (Shift+V).

render.<index>

Selects the 1-based renderer-combo entry and performs the same controlled restart as the UI. The machine-specific mapping is logged as Renderer order: render.N = name. An unavailable index is ignored safely.

[event_actions] actions

Comma-separated action identifiers. Each needs one [event_actions.<name>] section. Actions run only after successful refresh transitions.

on

One or more of refresh.applied (request succeeded), refresh.confirmed (new rate confirmed), and refresh.restored (previous rate restored).

when

Required expression using $actual_refresh, $requested_refresh, and $previous_refresh. It is evaluated from the completed transition snapshot.

program

Required .exe, .bat, or .cmd path. An empty/unsupported extension fails configuration validation.

arguments

Optional argument string passed to the program. Keep shell quoting appropriate to that program.

working_directory

Optional process working directory. Omit when the program does not rely on relative files.

delay_seconds

Whole seconds 0–30 before this action runs. Omission inherits [general] event_action_delay_seconds.

[event_actions]
actions: audio_delay_film

[event_actions.audio_delay_film]
on: refresh.applied,refresh.confirmed
when: $actual_refresh==23.976 || $actual_refresh==24
program: C:\Videoprocessor\audio\audio_delay.bat
arguments: 315
delay_seconds: 2

Diagnostics and troubleshooting

SymptomWhat to check
Section or key ignored/rejectedUse the exact section/key in the field index. Strict configuration reports the offending section and key; duplicate keys are not a supported override mechanism.
A vpvr setting has no effect with madVRExpected: vpvr.* is owned only by VideoProcessor Renderer (Alpha). Use shared capture/shader/viewport settings for cross-renderer behavior.
AUTO differs from expectationRead the field-specific AUTO paragraph. Then inspect libplacebo settings, output negotiation, source metadata, and OSD values; AUTO is not one global policy.
Wrong scaler result or dropped framesToggle the stats overlay, compare render time with the frame interval, and step from high → balanced → fast or Lanczos → bicubic → bilinear. Change one control per comparison.
Wrong black/white levelsCompare configured and actual output_range in output-negotiation logs and verify the display expects the same range.
Wrong colour/gammaCheck source transfer/primaries, SDR input override, target primaries, requested range/gamma, actual DXGI contract, and display mode as separate stages.
LUT not activeOSD/log reports missing path, parse error, target-contract mismatch, or render error. Make reference fields match the actual output contract.
Profile rule does not matchCompare logged source snapshot with expression types/values. Check priority and group order; text comparisons are case-insensitive.
Refresh switching does not occurConfirm switch_refresh_rate: true, source cadence, requested/actual refresh, and that Windows/display accepted the transition.
Changing a profile rebuilds the rendererExpected for input, scaling, display, LUT, and renderer-policy changes. Viewport-only changes normally apply live; the log states whether rebuild was required.
Shader missing or failsConfirm filename and renderer-compatible extension under deployed shaders. Compilation/installation failure is logged and the affected effect is disabled.

Glossary

HDR / SDR
High dynamic range / standard dynamic range.
EOTF / transfer
The relationship between stored signal values and displayed light.
LLDV
Low-Latency Dolby Vision, captured here without its HDMI vendor information frame.
LUT
Look-up table; here, a 3D display colour transform in .cube format.
NLS
Nonlinear stretch: redistributes horizontal geometry toward a wider physical viewport.
CIH
Constant image height; typically a scope-width screen/viewport such as 2.35:1.
PPM
Parts per million, a very small cadence/timing correction.
OSD
On-screen display.
