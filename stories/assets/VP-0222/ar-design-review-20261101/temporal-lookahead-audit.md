# Temporal, lookahead and performance audit

Reviewed source: 25a6abfd, native-boundary-cadence-20261031. Read-only review; no runtime changes or builds. Scope: live HDMI 23.976/59.94/60, variable aspect films/TV. The preexisting Black startup readiness failure is separate.

## Required temporal contract

An AR decision belongs to an immutable source image, not the refresh currently showing it. An already-proved decision must become effective on the FIRST displayed source to which its proof applies. Queued future images can corroborate that source without adding a runtime wait. Never apply a future frame's geometry early to an older displayed source. Distinguish observation time, proof-ready time, effective source, selected/displayed source, and actual submission time.

Native picture measurement, accepted native geometry, and displayed fitting/caption crop are different facts. Missing current measurement means UNKNOWN, even if the display retains valid older geometry. A repeat retains the whole original image and original metadata; it does not become a measurement of the consumed newer input. Screen ratio and remembered/standard ratios cannot manufacture measurement.

## Current execution order and budgets

1. Queue owns accepted immutable input identities; conversion must be ready before a decoded DV view is usable. Selection snapshots current + available future inputs. RenderThread explicitly says never wait for additional proof frames (LibplaceboVideoRenderer.cpp ~26120). The configured lookahead maximum is 8, and is a cap rather than evidence of actual readiness.
2. PrimeSubtitleMeasurements performs nonblocking render/settings checks, source preparation and asynchronous per-source requests, then publishes only source-owned completed windows. Late harvest after native analysis does not submit new work. Both entry and i0 require local policy/continuity/viewport equality (~24444 onward). A recorded queue retirement can leave local continuity behind until RenderLocked; this is a known separate startup availability risk, NOT established as a new observer regression.
3. Optional native work is admitted by PresentationAnalysisBudget: repeated interval or backlog => zero ticket; unqualified display timing => 1 ms; qualified phase => at most 2 ms, reserving max(2 ms, 1.25 * measured mandatory presentation cost, 0.95 * previous reserve). Mandatory work >= one refresh period => zero optional admission. Tickets expire at a fixed QPC deadline; no rollover or extra sleep.
4. Native lookahead measurement runs asynchronously; exact current identity/domain is checked. A missing head cannot be replaced by a later ready sample. Results form a contiguous ready prefix. A missing tail reduces effective depth, rather than counting as empty/black/absent.
5. SubmitPreparedLookaheadObservation consumes already-computed adjacent source facts independently of the sparse scan clock (~25449). This avoids the prior 80 ms throttle discarding ready evidence. Buffered outward proof needs current plus two qualified ready sources (OUTWARD_PICTURE_CONFIRMATIONS_REQUIRED=3). Buffered inward replays a copy of the live model over the exact ready prefix, then binds the resulting decision back to its first source.
6. Live UpdateNlsGeometry (~11065) still has a sparse cold ShouldAnalyze clock: round(fps * .080), clamped 1..6. That means every 2 inputs at23.976, every5 at59.94/60. Established excluded pixels force per-source safety inspection; scheduled/buffered proof also bypasses sparse admission. INITIAL_CONFIRMATIONS=4 and CLEAR_TRANSITION_CONFIRMATIONS=2 are model requirements, not a 24-frame dwell. A 24-source stable window in integration tests proves persistence; it is not permitted runtime latency.
7. Adoption validates exact source, baseline, policy/continuity, format/domain/viewport and current pixels. Native picture expansion must defeat stale subtitle presentation ownership. Downstream Classic drift, advanced composition, optional fill and scene retention must not change the detector measurement or postpone independently proven new native geometry.
8. SourceCadencePresentation retains successful final RGB only. All-source analysis is the default: InputFrameAnalysisDue defaults true, and workers use stride1. Ordinary whole-output repeat requires >30 Hz DECLARED input rate, immediate sequence+1, source PTS delta <=1.5 input periods, complete matching context and one unused anchor. Present code additionally bounds wall age. Progressive/inactive-temporal only; unsupported contexts analyze fresh instead. Mode/format/domain/policy/continuity/reset/output/HDR changes fail closed. The distinct first-Ready warmup bridge has its own preparation-key proof and current-native-handoff veto; it is not generic analysis reuse.
9. Raw analysis completion and caption presentation readiness differ. Three detected lines do not by themselves certify acquisition/erasure. Worker RAW predecessor archive preserves up to3 authentic past source facts for current four-source pixel comparison; it cannot restore expired current READY permission, semantic cue, native votes or lease. Queue-only reuse requires a typed timeline witness; seek/reset/unknown boundary is not a queue-only gap.

Input periods:23.976 =>41.708 ms;59.94 =>16.683 ms;60 =>16.667 ms. Existing two-future outward corroboration spans83.417/33.367/33.333 ms of capture history. With already-buffered ready evidence this is ZERO added presentation intervals. It is not an instruction to wait those milliseconds after seeing the changed displayed frame.

Four future slots cover166.833/66.733/66.667 ms of source history;3 slots125.125/50.050/50 ms;5 slots208.542/83.417/83.333 ms. Configured depth does not establish actual queue age, conversion readiness, worker completion, or end-to-end HDMI latency. Record each separately.

Proposed acceptance budgets (design targets, not measured guarantees):
- Proof ready before current render decision: zero source-frame delay to geometry adoption for that effective source.
- Proof becomes ready after selection: never relabel a later source with an earlier measurement; report unavailable-at-selection separately from avoidable adoption delay.
- Intentional skipped input at>30 Hz: at most one original complete image repeated once; next analyzed source fresh, no cue/history/lease renewal. No repeated renewal to disguise sustained overload.
- Optional fresh CPU scans stay inside existing1/2 ms presentation tickets; exact ready-certificate lookup/adoption needs a separate bounded cheap path. Do not make an expired optional scan ticket invalidate an already-ready exact certificate.
- With two subtitle workers at60fps, mean CPU demand must remain below33.33 ms/source aggregate capacity, with headroom for native analysis/render/capture. A21 ms scan can fit two workers on average but leaves little tail margin; p95/p99 completion lead and queue starvation matter more than average scan time. Do not use average1.9 ms live measurements as proof that difficult21 ms caption cases always meet deadlines.

## Conflicts / consolidation proposals

A. Sparse80 ms cold acquisition versus instant inward transition from retained FULL_RASTER is a real contract tension when ready lookahead is absent. Do not blindly remove safety confirmations. First measure whether ready facts were missing, discarded, or merely delayed by the clock. Separate scan scheduling from evidence consumption so any authentic ready source can advance proof immediately.
B. AnalyzeActivePictureLookahead currently aborts at an expired ticket at entry and again before prefix publication (~24643,25143). Even cached ready work may therefore be discarded when a positive ticket expires. cachedOnly mode avoids the timer, but a deadline that expires after dispatch is different. Audit/test this explicitly before optimizing: optional-work deadline should forbid additional scans, not invalidate previously available exact proof. This is a design risk, not a proven regression from the present logs.
C. Replace chains of loosely related held/available/complete flags at major interfaces with typed immutable packets: Measurement(source, bounds, confidence/unknown reason, optional uncertainty interval); NativeDecision(effective source, original contributors, owner epochs, proof-ready QPC); Presentation(selected source, measured/native/display bounds, source PTS, successful submission, repeat provenance). Existing typed certificates should be consolidated at boundaries rather than replaced by a new global authority.
D. Keep already-ready consumption ahead of optional work; current source and its minimum proof prefix ahead of farther speculative futures; source-coalesce immutable full-scan work rather than launch duplicate jobs after queue-only epochs. No new wait, wider hold or speculative continuity bypass belongs in this observer patch.
E. Known/remembered ratios may prioritize bounded search ROIs, rank proposals, or nominate a return. Current source pixels must validate actual edges. Never snap measured2.3301 to2.35 or assume scope because the screen is2.35. Small genuine changes need explicit tolerance tests; deadbands must not hide meaningfulAR transitions.

## Fast faithful replay and validation architecture

Layer1 deterministic temporal replay: fake monotonic clock, explicit accept/prepare/worker-complete/proof-ready/dequeue/submit events, and the production timeline/model/admission functions. No sleeps or GPU. Vary available prefixes0..configured, delayed/out-of-order completions, source gaps, typed retirements, resets, format/rate/domain changes. Assert first effective source and exact contributor provenance, not only eventual stability. Store arbitrary worker completions before/after render deadlines to reproduce timing deterministically.

Layer2 pixel corpus replay: original native capture bytes plus exact format, range, bit alignment, transfer/DV interpretation, identity, per-frame guard provenance and independently annotated true boundary/uncertainty. Reuse production extraction and source observers; no fitting involved. Generate caption/UI/noise/motion mutations with known pixel masks and run all source facts unpaced for speed. Existing64 and56 captures establish useful boundary cases but cannot prove continuous59.94 scheduling: they are sampled inputs, not complete full-rate runs.

Layer3 paced production integration: the existing real plugin/DXGI path with persistent source callback identity and incremental proof index, declared rational cadence and QPC arrival audit. Require actual59.94/60 arrival distribution, no O(N^2) diagnostic processing, no busy waits masquerading as playback. Repeat tests check exact whole image/cue/crop/HDR/PTS provenance and the fresh successor. Run cold shader qualification separately from warm detector transitions, retaining the user's explicitly allowed Missing/Pending clipping exception; no post-Ready grace interval.

For each scope→IMAX and IMAX→scope case, mark sourceK first changed frame, current-only proof-ready and full-prefix proof-ready events, source first adopted, and first submitted crop. Assert no prior source uses new geometry, first proven current source uses it, subsequent stable outputs stay correct. Exercise with subtitles absent/present/onset/offset/three-line/bar UI, both Classic and advanced,24-to60 output cadence and60-to60, analysis budget0/expired/ready, known and novelARs, flash/fade/dark scene and truly moving boundaries. Include raw input rate59.94 with repeated film frames as well as actual60 distinct motion; distinct source identities must not become fake independent pixel confirmations.

Capture/benchmark data needed: contiguous full-rate source sequence around a real transition (at least2s before/after), source/rational PTS, callback QPC, decoder/conversion completion, worker enqueue/start/finish, head ownership/retire reason, readiness prefix, proof contributors/QPC, adopted geometry, selected source and actual Present result/QPC. Sparse screenshots cannot establish transition latency. Long captures may use bounded full-frame ring plus cheap every-source ROI/hash/metadata, but the saved transition must include all full source frames used as proof. Report measurement error, first-proven latency, false crops, clipped picture/captions, repeat count, deadline misses, max/p95/p99 scan cost and frame delivery jitter separately.

## OSS comparison constraints

FFmpeg cropdetect provides useful spatial robustness principles: line averaging and outlier handling, and a separate motion/edge mode. Its whole-clip accumulation/reset policy and decoder motion-vector availability are not a live HDMI first-source transition contract. Hyperion demonstrates inexpensive spatial sampling, but its symmetric border-size/ambient-light objective does not establish safe asymmetric per-row movie crop authority. Use these as benchmark comparators on the same pixel corpus, not as replacements for exact source ownership or current-caption safety.

## Independent critique / release boundary

The design is sound only if instant means first already-proven displayed source, not guaranteed exact measurement of an uninformative dark image. Aggressively predicting scope from memory would hide uncertainty and recreate false crops. Conversely, labelling a good current measurement UNKNOWN because an unrelated caption shader is compiling violates separation. Keep physical observer output independent, expose UNKNOWN reasons honestly, and retain old display geometry only as an explicitly labelled presentation choice. Detector-positive changes must not absorb the existing Black startup-prefetch gap merely because a full timing-sensitive run exposes it.
