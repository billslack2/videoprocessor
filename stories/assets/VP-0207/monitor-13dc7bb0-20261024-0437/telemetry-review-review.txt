Immediate versus sampled events

1. SUBTITLE LIP — renderer 14083–14126.
The call exists only for valid move geometry, no already-valid generatedCleanup, and background 3/5. It logs immediately when reason, context-reject mask, cue-plane reason, or the post-Apply cleanup rectangle differs from the previously logged value. A normal evaluated applied→missing→applied cap cycle changes that rectangle and logs both edges even if only one source frame is affected. Otherwise it emits a heartbeat only when samples is nonzero and at least 2,000 ms elapsed. Stable zero-sample failure has no periodic heartbeat. At 23.976 sources/s an unchanged two-second heartbeat represents roughly 48 source intervals, not 48 individually recorded successes.
Other printed fields (valid, application reason, measured geometry, cue, sample count, plane-verified) are not independent change keys. In the normal applied case, applied is cleanup.Valid(), so the cleanup key catches its change. A skipped cap branch emits no LIP event and does not clear the prior log key: move-invalid/no-cue, already-generated cleanup, a different style, preparation reuse or measurement-disabled passes are not certified by this stream. An isolated skipped pass then identical recovery can be silent here; other evaluated layout/stability events may still report its cause.

2. SUBTITLE STABILITY — renderer 14250–14275; SubtitleBoxLookahead.h 3053–3114.
No time throttle. On consecutive distinct source identities in the same context, detector/accepted-visibility loss and regain, hold start/end, cue change and pending/confirmation changes cause immediate events. A one-source-frame visible→missing→visible cycle therefore produces loss and regain. suspected_flash is an additional recovery classification: same cue and a nominal accumulated gap >0 and <=500 ms. A loss does not require suspected_flash. At 23.976 sources/s one nominal source interval is about 41.71 ms.
Its visible input is accepted-result.detected && (not cut/paste or hookBound), not readback of displayed subtitle pixels. Exact SameAnalysisFrameIdentity repeats return before comparison. A nonconsecutive sequence, discontinuity or generation/policy/continuity change resets comparison, so the old loss edge is not inferred across that gap. The gap is nominal source-frame duration, not wall-clock output duration. Early preparation failure can return before Observe; disabled measurement resets it. A cap-only omission with valid glyph composition does not alter this visibility flag.

3. SUBTITLE CONTINUATION / CONTINUATION STATE — renderer 13905–13958.
CONTINUATION logs reason changes immediately or unchanged reason after 2,000 ms, but only with a nonzero template sequence and reason other than not-eligible. valid/complete/identity/coverage changes alone do not trigger it. A one-pass no-template/not-eligible interval followed by the same old reason may leave no CONTINUATION event. STATE logs changes in base_available, HasReference, seed reason, initial state, or a 2,000 ms heartbeat. Its printed preview/analyzed/raw_text/accepted/shared fields are not independent triggers; they can change briefly without a STATE record. A dropped guard reference may nevertheless expose an otherwise skipped CONTINUATION interval through STATE.

Common coverage limits and supporting streams
- All three streams above execute inside the non-reused subtitle-measurement preparation branch (renderer 13725–13743, 14394). motionDraw>0 can reuse exact source preparation and skip them. A separate cadenceRepeat at motionDraw=0 is not this bypass, although STABILITY itself ignores an exact repeated identity (RenderLoop 24644, 24658). This distinction prevents treating source events as per-output telemetry.
- SUBTITLE LAYOUT is immediate for validity/cue/destination/layoutContent/glyph-transform changes (14128–14159). Cleanup-only difference is not in its trigger, even though accepted-cleanup-change is one possible displayed reason after another trigger fires.
- BBOX/MOTION/CAPTURE detail shares a gate: cue change, revised result, sequence divisible by 120, or an analysis-reason/work-limit/gap-presence change at least 250 ms after its last detail log (14297–14303, 14387–14391). Thus brief diagnostic changes can be sampled away. At 23.976 sources/s the every-120-source fallback is about 5.01 s, assuming consecutive sequences.
- Submitted geometry is an output-submission event, but its trigger compares generation/viewport and source/target rectangle coordinates at >=0.5 pixel (renderer 19060–19092; SubmittedOutputGeometryTrace.h 12–23). No timer suppresses a tracked one-output geometry excursion. Glyph/cap composition flags are metadata, not trigger keys; unchanged geometry does not establish unchanged subtitle pixels.
- Explicit failures have other markers: failSubtitleMotion emits on failure-status change before returning false (13677–13686); ordinary composition failure logs at 14240; the libplacebo failed-render black-clear path logs each entry at 19033–19040. Their absence constrains those reported failures, not every possible pixel defect.

Log delivery
DebugLog.h 55–66 formats messages immediately, forwarding to the host sink if installed. The host queue is asynchronous; 50-message/100-ms flushing is delivery batching, not event sampling (212–214). Timestamps have one-second precision (209, 278), so frame IDs/order are needed for subsecond transitions. The queue drops its oldest entry when already at 1,000 messages (224–228); this code provides no drop marker. No queue loss is demonstrated in the preserved session. These delivery limits prevent an unconditional assertion that absent records prove absent visual events.
