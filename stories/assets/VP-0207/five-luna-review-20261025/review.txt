2. Missing owner provenance limits a safe repair

PresentationEnvelopeExtentState records bounds, base, source identities and timers, without caption-versus-UI ownership or subtitle mode (AlphaSourceCropPolicy.h:756-764; cpp:1991-2076). Raw history can include caption, UI or transient picture evidence. A global history clear, or treating no-bright-ink as permission to crop, would be unsafe.

ConfirmedSubtitleAbsentForPresentation is a completed subtitle-search predicate, not a proof that all pixels in a historical extent are absent. It lacks the final native-base/retention contract (SubtitleAspectRetention.h:185-195). excludedBandsPixelSafe is sampled (ActivePictureEvidence.cpp:589-597); visible-extent detection uses sparse samples (:721 onward). Dim text or small icons can evade these tests. Prepared-erasure proof has different semantics. Pending/active translation and genuine picture expansion also need explicit handling.

Discussion outcome: reject a blanket no-caption/coarse-safe shortcut. Investigate one consistent mode-specific presentation owner with caption/UI provenance and bounded lifetimes. Any narrowly qualified absence path must bind exact current source, policy/continuity, native base and current pixels across the relevant extent, while retaining fallback for unknown or visible content. This is a design direction for qualification, not an implemented or proven fix.

4. Separate logical reset race in the DirectShow analyzer

CBufferedLiveSourceVideoOutputPin::ResetSubtitleAnalysis increments the generation and clears tracking/bar atomics before acquiring m_subtitleAnalysisMutex (microsoft_directshow/live_source_filter/CBufferedLiveSourceVideoOutputPin.cpp:5084-5103). An old worker can finish analysis after the reset and unconditionally republish trackActive and picture edges (:5293-5300). Only the later latest-result publication is generation-checked (:5306-5323).

A feasible interleaving is old worker Analyze -> reset clears state -> old worker publishes old tracking/bar atomics -> old latest result is rejected. Stale or mixed atomic tuples can influence signature sampling and next analyzer cadence (:5116-5194). This is a logical stale-publication race, not an unsynchronized C++ data race. The compositor still checks result generation/age, limiting impact.

A pre-store generation check alone does not close the race because reset can occur between check and stores. Reset generation/clearing and publication need common serialization with the check inside it, or a versioned coherent snapshot; readers of the tuple need the same consistency contract. A forced interleaving test is required.

The concurrency and reset reviewers agree this is outside the incident's Libplacebo path: GUI selects LibplaceboPluginVideoRenderer for this runtime, whereas CBufferedLiveSourceVideoOutputPin belongs to CLiveSource's DirectShow pipeline. Confidence: concrete code-level ordering risk; very low incident relevance; no executed interleaving test or live failure claim.
