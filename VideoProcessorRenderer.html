VideoProcessor built-in renderer configuration

VideoProcessorRenderer.cfg contains settings for the experimental built-in libplacebo renderer. It is searched first beside the executable, then up to two parent directories, with the application's working directory as a fallback. It uses INI-style sections and key=value entries. Blank lines and lines beginning with # are ignored.

Renderer selection and application-wide capture, timing, and queue options remain in VideoProcessor.cfg. For example, select the built-in renderer there with:

[command_line]
renderer=libplacebo

Application-wide settings and shader rules remain in VideoProcessor.cfg. See VideoProcessor configuration for those settings.

Optional renderer installation

The normal VideoProcessor executable has no libplacebo dependency and can be distributed by itself. To add the experimental renderer, place the complete optional renderer pack in a libplacebo directory beside the executable:

VideoProcessor.exe
libplacebo\
  VideoProcessorLibplacebo.dll
  libplacebo-360.dll
  required runtime DLLs...
  third_party_licenses\

VideoProcessor loads only libplacebo\VideoProcessorLibplacebo.dll. If the plugin, one of its private dependencies, or the expected plugin API is unavailable, the application starts normally and does not list the experimental renderer.

[display] (experimental libplacebo renderer)

The built-in renderer uses D3D11 and always produces SDR Rec.709 output. SDR input is color-managed without HDR tone mapping; PQ, HLG, traditional HDR, and detected LLDV input are tone-mapped to SDR using VP's effective input colorspace and mastering metadata. Changes between HDR and SDR are accepted in place.

KeyValuesEffect
sdr_target_nits40 through 500; default 203Brightness of the SDR tone-mapping target. The default follows libplacebo's BT.2408 SDR reference-white model. This describes the intended SDR output level, not an HDR output mode.
sdr_black_nitsAUTO or a non-negative number below sdr_target_nitsBlack level of the SDR display. AUTO uses libplacebo's nominal 1000:1 SDR contrast assumption. A measured display or projector black level can improve tone-mapping accuracy.
switch_refresh_rateBoolean; default trueSwitch the active render monitor to the captured cadence while this renderer is active, without changing its resolution or display topology. Progressive 23/24 Hz uses its native rate; progressive 25/29.97/30 Hz and interlaced input use the matching doubled display rate. The previous refresh rate is restored when the renderer closes. A failed or unsupported switch is logged and rendering continues at the current rate.
qualityfast, balanced, or high; default highSelects libplacebo's rendering preset. high preserves VP's original experimental-renderer behavior. Individual AUTO settings inherit from this preset.
tone_mappingAUTO, spline, bt2390, st2094-40, or reinhardSelects the HDR-to-SDR tone-mapping curve. AUTO uses the quality preset; the current presets use spline.
gamut_mappingAUTO, perceptual, softclip, relative, or desaturateSelects how wide-gamut input is mapped into SDR Rec.709. AUTO uses the preset's perceptual mapping.
peak_detectionAUTO, ON, or OFFControls dynamic HDR peak measurement. AUTO inherits from the quality preset.
contrast_recoveryAUTO or 0.0 through 1.0Restores high-frequency detail after tone mapping. Higher values can increase apparent detail but may introduce ringing. AUTO inherits the preset; high quality currently uses approximately 0.30.
upscalerAUTO, ewa_lanczossharp, ewa_lanczos, bicubic, or bilinearSelects image upscaling. AUTO inherits from the quality preset.
downscalerAUTO, ewa_lanczos, bicubic, or bilinearSelects image downscaling. AUTO inherits from the quality preset.
debandAUTO, ON, or OFFControls libplacebo debanding. AUTO inherits from the quality preset.
ditheringAUTO, ON, or OFFControls output dithering. Explicit ON uses libplacebo's blue-noise default.
output_rangeAUTO, FULL, or LIMITED; default AUTOSets the renderer's RGB output encoding independently of captured-frame metadata and DirectShow overrides. FULL uses 0-255 at 8-bit (0-1023 at 10-bit). LIMITED uses 16-235 at 8-bit (64-940 at 10-bit). AUTO preserves the negotiated display/swapchain range.
output_gammaAUTO, BT1886, SRGB, 1.8, 2.0, 2.2, 2.4, 2.6, or 2.8; default AUTOSets the SDR output transfer curve used by libplacebo's color-managed render target. AUTO preserves the negotiated display/swapchain transfer. This does not reinterpret the input EOTF.
scope_screen_aspectA decimal or width:height ratio from 1.5 through 4.0; default 2.35:1Defines the physical aspect ratio of a constant-image-height screen. Examples include 2.35:1, 2.39:1, 2.40:1, or 1.7778. In the Scope profile the renderer fits the image into a centered viewport with this aspect ratio; narrower content is pillarboxed inside it.
scope_subtitle_fittrue or false; default falseIn the Scope profile, detects subtitle-like text extending into the lower encoded black bar and moves the complete rendered picture upward only far enough to keep that text on the visible screen. The position is held briefly between subtitle lines and then returns to center. Detection uses frame geometry and does not require an OCR model.
default_screen_profilenormal or scope; default normalSelects the startup profile when no saved selection exists. The renderer-specific shortcuts below select either profile immediately and save it in VideoProcessorRenderer.state beside the executable. Delete that automatically managed state file to return to this configured default.
lutOptional path to a .cube 3D LUTApplies a display-calibration LUT to the encoded target RGB after tone mapping, gamut mapping, and target transfer encoding. Relative paths must remain below the configuration directory, including after junction/symlink resolution; explicit absolute paths are allowed. Files over 64 MiB, malformed files, any file declaring a 1D LUT, and cubes larger than 128 entries per axis are rejected safely. Omit or leave blank for no LUT.
lut_reference_primariesAUTO, rec709, p3_d65, or bt2020Primaries of the encoded RGB expected by the calibration LUT. AUTO resolves to the accepted output target. An explicit mismatch rejects the LUT. P3-D65 is currently rejected because the Windows presentation path has no verified P3 signal contract.
lut_reference_transferAUTO, sRGB, BT1886, 2.2, or 2.4Transfer encoding expected at the LUT input. Full-range output normally resolves to sRGB/G22; verified limited output resolves to gamma 2.4.
lut_reference_rangeAUTO, full, or limitedRGB range expected by the LUT. If output negotiation falls back to another range, an explicit profile is rejected instead of being applied to the wrong values.
lut_reference_nitsAUTO or 40 through 500Reference white/peak level used to author the LUT. AUTO resolves to sdr_target_nits.

Set lut in the base display section for every display profile, or set it in a selected [display_rules.name] section for a profile-specific calibration. LUTs are parsed once when that renderer profile starts. The Ctrl+I display shows LUT: Active, Disabled, or a short Rejected reason. Rejected files and target-contract mismatches retain ordinary no-LUT playback.

[display_rules.bt2020]
lut=lut\bt2020-calibration.cube
lut_reference_primaries=bt2020
lut_reference_transfer=sRGB
lut_reference_range=full
lut_reference_nits=100

[shortcuts]

These shortcuts apply only to the optional renderer and belong in VideoProcessorRenderer.cfg. screen_profile_normal selects the full 16:9 output raster; screen_profile_scope selects the configured scope viewport. Direct selection keeps VP aligned with projector lens-memory or screen-masking commands. Function keys F1 through F24, letters, numbers, Escape, and Enter are supported with optional Ctrl, Alt, and Shift modifiers.

[shortcuts]
screen_profile_normal=F2
screen_profile_scope=F3
The renderer supports V210, UYVY, ARGB, BGRA, R10b, R10l, and R12L capture formats through VP's P010 conversion path. It does not emit HDR or require Windows HDR mode.
